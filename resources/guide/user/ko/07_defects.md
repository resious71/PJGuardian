## 결함 화면 열기

- 프로젝트 상세의 {{ui:defects.tab}} 탭, 또는 {{icon:nav.defects}} 메뉴에서 프로젝트를 골라 결함 목록을 엽니다.
- 목록에서 결함을 누르면 결함 상세로 이동합니다. 상세에는 결함 정보, 수정 폼, 코드([코드 뷰어](guide:code-viewer)), 변경 이력이 있습니다.
- 규칙 이름을 누르면 [규칙 설명](guide:rules)으로 이동합니다.

결함은 분석 도구가 찾은 문제 하나입니다. 다시 분석해도 같은 결함으로 추적되며, 파일 경로와 규칙, 해당 코드 내용으로 같은 결함인지 판단합니다. 줄 위치만 바뀐 경우에도 대개 같은 결함으로 봅니다. 파일을 옮기거나 이름을 바꾸면 기존 결함은 해결로, 새 위치의 결함은 신규로 잡힙니다.

![프로젝트 상세의 결함 영역. 위에 Run 표시줄, 그 아래 검색 조건(검색어·파일·심각도·상태·규칙·담당자·정렬)과 검색 단추, 결과 건수와 내보내기 단추가 있습니다.](guide-img:defect-list)

## 심각도

{{icon:severity.critical}}, {{icon:severity.high}}, {{icon:severity.medium}}, {{icon:severity.low}}, {{icon:severity.not_defined}} 중 하나입니다.

- 새 결함은 규칙마다 정해진 기본 심각도로 자동으로 정해집니다. 기본값이 없는 규칙은 미지정입니다.
- 사람이 바꾼 심각도는 이후 분석에서 바뀌지 않습니다.
- 심각도 옆 표시에 마우스를 올리면 "규칙 기본값"인지 "수동 변경"인지 보입니다.

## 상태

{{icon:defect_status.open}}, {{icon:defect_status.in_progress}}, {{icon:defect_status.postponed}}, {{icon:defect_status.intentional}}, {{icon:defect_status.not_fix}}, {{icon:defect_status.resolved}} 중 하나입니다.

- 새 결함은 열림으로 시작합니다.
- 상태는 어떤 값으로든 자유롭게 바꿀 수 있습니다. 각 상태를 언제 쓸지는 팀에서 정하세요.
- 분석이 상태를 자동으로 바꾸기도 합니다(아래 "자동 해결과 재오픈").

## 담당자·심각도·상태 바꾸기

1. 결함 상세의 "{{ui:defects.edit_title}}"에서 값을 고릅니다.
2. 필요하면 "{{ui:defects.memo_label}}"를 적습니다. 사유는 변경 이력에 함께 남습니다.
3. {{ui:defects.save}}를 누릅니다. 바뀐 값이 없으면 저장 단추가 꺼져 있습니다.

담당자로는 그 프로젝트를 볼 수 있는 활성 사용자만 고를 수 있습니다. 이미 담당자인 사람이 비활성화되거나 프로젝트 접근을 잃어도 담당은 그대로이고, "비활성" 또는 "접근 권한 없음" 표시가 붙습니다. 접근을 잃은 담당자에게는 그 결함이 내 결함에 나오지 않습니다.

## 일괄 변경

1. 결함 목록에서 바꿀 결함의 선택 칸을 고릅니다. "{{ui:defects.select_page}}"로 현재 페이지를 한꺼번에 고를 수 있습니다.
2. 바꿀 항목(담당자·심각도·상태)만 고릅니다. "(바꾸지 않음)"인 항목은 그대로 둡니다.
3. 필요하면 사유를 적고 {{icon:action.bulk_edit}} {{ui:defects.bulk_apply}}를 누릅니다.
4. 확인 창에서 내용을 확인합니다.

- 선택은 현재 페이지 안에서만 됩니다. 한 번에 바꿀 수 있는 최대 건수: {{limit:ui.bulk_update_max}}
- 결과는 "변경 / 변경 없음 / 충돌" 건수로 나옵니다. 그사이 다른 사람이 바꾼 결함은 바꾸지 않고 최신 값과 함께 목록으로 알려 줍니다.
- 이력은 결함마다 따로 남습니다.

## 변경 이력

결함 상세의 {{ui:defects.history_title}}에 최신순으로 나옵니다. 시각, 변경자, 항목, 이전 값과 이후 값, 구분(수동·자동), 사유가 보입니다. 분석이 바꾼 것은 "자동"으로 표시되고 사유가 함께 나옵니다.

## 자동 해결과 재오픈

분석이 **성공했을 때만** 결함 상태가 자동으로 바뀝니다. 실패하거나 취소된 분석은 어떤 결함도 바꾸지 않습니다.

- 이번 분석 범위의 파일에서 더 이상 감지되지 않음: 해결됨으로 바뀝니다(사유 "분석에서 더 이상 감지되지 않음").
- 이번 업로드에 파일이 없음: 해결됨으로 바뀝니다(사유 "파일 삭제").
- 제외 대상에 해당하는 파일: 분석 범위 밖이므로 상태를 그대로 둡니다. 파일 삭제와 구분됩니다.
- 해결됨인 결함이 다시 감지됨: 열림으로 다시 열립니다(사유 "다시 감지됨"). 사람이 해결됨으로 바꿨는데 계속 감지되는 경우도 같습니다.

자동 해결은 보류·의도됨·수정 안 함을 포함해 지금 상태와 관계없이 일어나고, 이전 상태는 이력에 남습니다. 그래서 일부 파일만 올리면 빠진 파일의 결함이 "파일 삭제"로 해결됩니다. 매번 프로젝트 전체를 올리세요.

## 동시 수정 충돌

내가 결함을 연 뒤 다른 사용자나 분석이 먼저 바꿨다면 저장이 거부되고 "다른 사용자가 먼저 변경했습니다" 창이 열립니다.

1. 창에서 "내가 입력한 값"과 "최신 값"을 비교합니다. 먼저 바뀐 항목은 따로 표시됩니다.
2. {{ui:defects.conflict_retry}}를 누르면 최신 값을 기준으로, 내가 바꾸려던 항목만 다시 적용합니다. 입력한 사유는 지워지지 않습니다.

## 검색과 필터

결함 목록 위의 검색 영역에서 조건을 고릅니다.

- 검색어: 메시지, 규칙, 파일 경로의 일부
- 파일: 경로로 시작 또는 경로에 포함
- 심각도·상태: 칩을 눌러 고릅니다. 칩의 숫자는 마지막으로 적용한 나머지 조건 기준의 건수입니다.
- 규칙·담당자: 목록에서 고릅니다. Ctrl(⌘)을 누른 채 누르면 여러 개를 고를 수 있습니다.
- 정렬과 순서, Run 조건(새로 생긴 Run, 존재한 Run)

조건을 고르기만 해서는 목록이 바뀌지 않습니다. 맨 아래 {{icon:action.search}} {{ui:defects.apply}}를 누르거나 검색어·파일·Run 입력칸에서 Enter를 누르면 한꺼번에 적용됩니다. 고른 뒤 아직 적용하지 않았으면 "조건이 변경되었습니다" 표시가 나옵니다. {{icon:action.filter}} {{ui:defects.clear_filters}}는 바로 적용됩니다. 적용한 조건은 주소에 남으므로 링크로 공유하거나 뒤로 가기로 돌아올 수 있습니다.

목록은 한 페이지에 {{limit:ui.defect_page_size}}건씩 보입니다.

## 내 결함

{{icon:nav.my_defects}} 메뉴는 내가 담당자인 결함을 모아 보여 줍니다. 볼 수 있는 프로젝트의 결함만 나오며, 상태와 프로젝트로 거를 수 있습니다. 수정은 결함을 눌러 결함 상세에서 합니다.

## 과거 Run 보기

결함 목록과 상세 위의 Run 선택기로 과거 Run 시점을 볼 수 있습니다. 과거 Run은 {{icon:ui.read_only}} 읽기 전용이라 수정과 일괄 변경을 할 수 없습니다. 자세한 내용은 [히스토리](guide:history)를 보세요.
