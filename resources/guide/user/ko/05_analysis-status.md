## 분석 상태 보기

업로드가 대기열에 들어가면 분석이 하나 만들어집니다. 진행 상황은 다음 화면에서 봅니다.

- 프로젝트 상세의 {{ui:analyses.tab}} 탭: 이 프로젝트의 분석 목록(최신순). "실행 주체"로 사용자 실행과 주기 실행을 나눠 볼 수 있습니다.
- 분석 상세: 목록에서 분석을 누르거나 업로드 화면의 "{{ui:upload.go_analysis}}" 링크로 엽니다. 진행 중인 분석은 화면이 자동으로 갱신됩니다.

## 상태의 뜻

- {{icon:analysis_status.queued}} (queued): 대기열에서 차례를 기다립니다. 분석 상세에 대기 순번이 보입니다. 순번은 대략적인 값입니다.
- {{icon:analysis_status.running}} (running): 분석 도구가 실행 중입니다.
- {{icon:analysis_status.succeeded}} (succeeded): 분석이 끝나고 결과가 결함에 반영되었습니다.
- {{icon:analysis_status.failed}} (failed): 분석이 끝나지 못했습니다. 결함은 하나도 바뀌지 않습니다. 원인과 조치는 [분석 실패 해결](guide:analysis-failures)을 보세요.
- {{icon:analysis_status.cancelled}} (cancelled): 사용자가 취소했습니다. 결함은 하나도 바뀌지 않습니다.
- {{icon:analysis_status.unchanged}}: 저장소에서 가져오는 분석에서만 나옵니다. 저장소의 최신 리비전과 분석 조건(도구 버전·설정·규칙·제외 패턴)이 직전 성공 분석과 같아 분석을 생략했습니다. 결함과 Run은 바뀌지 않고, 같은 리비전을 분석한 기준 Run이 함께 표시됩니다.

코드에 문법 오류가 있어도 분석은 성공합니다. 문법 오류는 `syntax-error` 결함으로 기록됩니다.

## 대기열 규칙

- 분석은 들어온 순서대로 처리합니다.
- 서버 전체에서 동시에 실행하는 분석 수: {{limit:analysis.max_concurrent}}
- 한 프로젝트의 분석은 한 번에 하나만 실행합니다. 같은 프로젝트의 다음 분석은 앞 분석이 끝날 때까지 기다리고, 그동안 다른 프로젝트의 분석이 먼저 실행될 수 있습니다.

## 분석 취소

대기 중이거나 실행 중인 분석은 요청한 본인 또는 관리자가 취소할 수 있습니다.

1. 분석 목록이나 분석 상세에서 {{icon:action.cancel}} {{ui:analyses.cancel}}을 누릅니다.
2. 확인 창에서 취소를 확인합니다.

- 대기 중이면 바로 취소됩니다.
- 실행 중이면 분석 도구를 멈춘 뒤 취소됩니다. 잠시 "취소 요청됨"으로 보입니다.
- 끝난 분석은 취소할 수 없습니다.

취소해도 결함 상태와 비교 대상(직전 성공 분석)은 바뀌지 않습니다. 다시 분석하려면 다시 업로드하세요.

## 성공한 분석의 결과

분석 상세의 결과 요약에서 다음을 봅니다.

- 감지된 결함 수, 심각도별 건수
- 신규: 이번에 처음 감지된 결함
- 해결: 이번 분석에서 자동으로 해결(resolved)된 결함
- 재오픈: 해결 상태였다가 다시 감지되어 열림으로 돌아간 결함
- 비교 대상: 직전 성공 분석. 실패·취소된 분석은 비교에서 뺍니다. 프로젝트의 첫 성공 분석은 비교 대상이 없어 모든 결함을 신규로 봅니다.

신규·해결·재오픈 숫자를 누르면 해당 결함만 걸러진 결함 목록으로 이동합니다. 자동 해결과 재오픈 규칙은 [결함 관리](guide:defects)를 보세요.

업로드한 설정 파일을 쓰지 않았거나 경고를 확인하고 진행한 분석이면 분석 상세에 안내가 함께 나옵니다.

## Run 번호

성공한 분석에는 프로젝트마다 Run 번호(Run 1, Run 2, …)가 붙습니다.

- 실패·취소된 분석에는 Run 번호가 없으므로 번호가 건너뛰지 않습니다.
- 성공(변경 없음)은 새 Run을 만들지 않습니다.
- 분석 목록과 상세에서 성공한 분석은 "Run N · 분석 #id"로 표시됩니다.

Run을 비교하는 방법은 [히스토리](guide:history)를 보세요.

## 주기 분석과 재시도

관리자가 주기 분석을 켠 프로젝트는 정해진 때에 저장소에서 코드를 가져와 분석합니다. 이런 분석은 분석 목록의 요청자 자리에 {{icon:source.schedule}}가 표시됩니다. 저장소 연결이 일시적으로 실패하면 "재시도 대기"로 보였다가 다시 시도할 수 있습니다.

## 주의

- 실패한 분석을 다시 실행하는 단추는 없습니다. 원인을 고친 뒤 다시 업로드하세요.
- 분석이 끝났다는 알림은 [알림](guide:notifications) 설정에 따라 받을 수 있습니다.
