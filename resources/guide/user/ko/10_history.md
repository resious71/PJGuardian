## 무엇을 하나요

{{icon:nav.history}} 화면은 한 프로젝트의 분석 결과가 시간에 따라 어떻게 바뀌었는지 보여 줍니다. 분석마다 직전 결과와 비교해 새로 생긴 결함과 해결된 결함을 확인할 수 있습니다.

분석의 진행·취소·실패 처리는 히스토리가 아니라 프로젝트의 "{{ui:analyses.tab}}" 탭에서 합니다([분석 상태](guide:analysis-status)). 히스토리 화면 위의 {{ui:history.to_analyses_tab}} 단추로 바로 갈 수 있습니다.

## Run과 분석 번호

- **분석**은 업로드나 가져오기로 시작된 작업 하나입니다. 대기, 실행 중, 성공, 실패, 취소 중 하나의 상태를 가지며 "분석 #번호"로 부릅니다.
- **Run**은 성공한 분석의 결과 회차입니다. 프로젝트마다 Run 1, Run 2, …로 번호가 붙습니다.
- 실패하거나 취소된 분석에는 Run 번호가 붙지 않습니다. 그래서 Run 번호는 건너뛰지 않고 이어집니다.
- 화면에서는 "Run 3 · 분석 #12"처럼 함께 표시합니다.

## 히스토리 열기

1. 상단 메뉴 {{icon:nav.history}}를 누르고 프로젝트를 고릅니다. 또는 프로젝트 화면 위의 {{ui:history.title}} 단추를 누릅니다.
2. 화면은 위에서부터 추이 차트, 비교 패널, 분석 이력 표 순서입니다.

## 추이 차트

"{{ui:history.chart_title}}" 차트는 최근 Run마다 신규·재오픈(위쪽)과 해결(아래쪽) 건수, 열린 결함 수를 보여 줍니다.

- "{{ui:history.chart_count}}" 상자에서 10, 20, 50개 중 볼 Run 수를 고릅니다.
- 차트의 점을 누르면 아래 비교 패널이 그 Run으로 바뀝니다.
- 마름모 표시는 그 Run에서 도구 버전이나 설정이 바뀌었다는 뜻입니다.
- {{ui:dashboard.show_table}}를 누르면 같은 값을 표로 봅니다.

## 직전 Run과 비교하기

비교 패널은 고른 Run을 **직전 성공 분석(직전 Run)** 과 비교합니다. 실패·취소된 분석은 비교에서 뺍니다. 프로젝트의 첫 Run은 비교 대상이 없어 모든 결함을 신규로 봅니다.

1. 분석 이력 표에서 원하는 행의 {{ui:history.show_compare}}를 누릅니다. 또는 차트의 점을 누릅니다.
2. 패널 위의 {{ui:history.prev}}, {{ui:history.next}} 단추로 옆 Run으로 옮겨 갑니다.
3. 카드에서 건수를 확인합니다.
   - **{{ui:history.card.new}}**: 이 Run에서 처음 감지된 결함
   - **{{ui:history.card.resolved}}**: 이 Run에서 감지되지 않았거나 파일이 삭제되어 자동으로 해결된 결함
   - **{{ui:history.card.reopened}}**: 해결됐다가 다시 감지되어 열린 결함
   - **{{ui:history.card.retained}}**: 직전에도 지금도 감지된 결함
   - **{{ui:history.card.out_of_scope}}**: 이번 분석 범위 밖이라 상태를 그대로 둔 결함
4. 카드의 "목록 보기" 링크를 누르면 그 결함만 거른 결함 목록이 열립니다.

패널에는 심각도별 분포와, 신규·해결 결함이 많은 상위 규칙·파일도 나옵니다.

## 버전/설정 변경 배지

분석 이력 표에서 {{icon:ui.changed}} 배지가 붙은 Run은 직전 Run과 비교해 도구, 도구 버전, 설정 출처, 설정 내용 중 하나 이상이 바뀐 Run입니다. 배지에 마우스를 올리거나 키보드로 포커스하면 무엇이 어떻게 바뀌었는지 보입니다.

이런 Run에서는 신규·해결이 코드 변경이 아니라 규칙 변화 때문일 수 있습니다. 비교 패널에도 같은 주의 문구가 나옵니다. 규칙이 어떻게 바뀌었는지는 [규칙 설명](guide:rules)의 버전별 변경 내역에서 확인하세요. 분석한 파일 수가 크게 달라졌을 때도 "분석 범위가 달라졌습니다" 안내가 나옵니다.

## 성공(변경 없음)

저장소와 연결된 프로젝트는, 저장소의 최신 리비전과 분석 조건(도구 버전·설정·규칙·제외 패턴)이 직전 성공 분석과 같으면 분석을 생략합니다. 이때 분석 이력에는 {{icon:analysis_status.unchanged}} 행이 생깁니다.

- 결함과 Run은 바뀌지 않습니다. 새 Run 번호도 생기지 않습니다.
- 행에는 확인 횟수와 마지막 확인 시각, 이미 분석한 기준 Run 링크가 보입니다.
- 이 행은 추이 차트와 비교에서 빠집니다.
- {{ui:history.hide_unchanged}}를 켜면 표에서 숨깁니다.

## 과거 Run 보기

프로젝트의 "{{ui:defects.tab}}" 탭과 결함 상세 위에 있는 Run 선택 상자에서 지난 Run을 고르면 그 Run 시점의 결함 현황을 봅니다. 기본은 최신 Run입니다.

- 키보드로는 화살표로 Run을 고른 뒤 Enter를 누릅니다.
- 과거 Run을 보는 동안에는 {{icon:ui.read_only}} "Run N 시점 보기(읽기 전용)" 안내가 나옵니다. 상태·담당자·심각도는 그 Run이 끝난 시점의 값입니다.
- 줄 번호와 메시지는 최신 감지 위치입니다.
- 과거 Run에서는 결함을 고칠 수 없습니다. 안내 옆의 최신 Run 이동 링크로 돌아가 바꾸세요.

결함 목록의 Run 열을 누르면 그 Run의 비교 패널이 열립니다.

## 주의

- 해결 목록은 "이 Run에서 해결된 결함"입니다. 그 뒤 다시 열린 결함도 들어 있으므로 목록의 현재 상태 열을 함께 보세요.
- 사람이 직접 해결됨으로 바꾼 결함은 해결 건수에 들어가지 않습니다. 해결 건수는 분석이 자동으로 해결한 결함만 셉니다.
- 오래된 Run은 상세가 삭제될 수 있습니다. 이런 Run에는 "{{ui:history.run_deleted_mark}}"이 붙고, 건수는 남지만 결함 목록으로 이동할 수는 없습니다.
- 분석이 하나도 성공하지 않았다면 비교할 결과가 없습니다. "{{ui:analyses.tab}}" 탭에서 실패 원인을 확인하세요([분석 실패 해결](guide:analysis-failures)).
