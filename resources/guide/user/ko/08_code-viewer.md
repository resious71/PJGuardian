## 무엇을 보여 주나

결함 상세의 {{ui:defects.code_title}} 영역에서 결함이 난 파일의 코드를 보여 줍니다.

- 결함이 **마지막으로 감지된 분석** 시점의 코드입니다. 지금 PC에 있는 코드나 가장 최근에 올린 코드와 다를 수 있습니다.
- 코드 위에 어느 분석(또는 Run) 시점의 어떤 파일인지 표시됩니다.
- Python, JavaScript, TypeScript 문법 색을 입혀 보여 줍니다.
- 줄 번호는 원본 파일 기준입니다.
- 읽기 전용입니다. 코드를 고치거나 저장할 수 없습니다.
- 코드는 항상 글자 그대로 보여 주므로, 코드 안에 HTML이나 스크립트가 있어도 실행되지 않습니다.

## 결함 위치 표시

결함 상세를 열면 코드가 결함 줄로 스크롤됩니다. 결함 줄은 배경색으로 표시되고, 도구가 열 범위를 알려 준 경우 그 부분에 물결 밑줄이 그어집니다.

## 보기 범위와 줄 바꿈

"{{ui:defects.code_mode_label}}"에서 고릅니다.

- {{ui:defects.code_mode_window}}: 결함 줄 앞뒤 일부만 보여 줍니다(앞뒤 줄 수: {{limit:viewer.code_window_lines}}).
- {{ui:defects.code_mode_full}}: 파일 전체를 보여 줍니다.

긴 줄이 화면 밖으로 나가면 {{ui:defects.code_wrap}}을 켜세요.

파일이 아주 크면 일부만 보이거나 열리지 않을 수 있습니다.

- 파일의 줄 수가 한도({{limit:viewer.code_max_lines}})를 넘으면 전체 파일을 골라도 결함 주변만 보여 줍니다.
- 한 줄의 길이가 한도({{limit:viewer.code_max_line_length}})를 넘으면 앞부분만 보여 줍니다.
- 파일 크기가 한도({{limit:viewer.code_max_file_size}})를 넘으면 뷰어로 열지 않습니다.
- 텍스트가 아닌 파일은 보여 주지 않습니다.
- 원본이 UTF-8이 아니면 일부 글자가 대체 문자로 보일 수 있습니다.

## 코드 스냅샷과 발췌본

분석이 성공할 때마다 분석한 파일의 코드를 스냅샷으로 보관합니다.

- 프로젝트마다 최근 성공 분석 몇 회분(현재 설정: {{limit:snapshot.full_keep_count}})은 전체 코드를 보관합니다.
- 그보다 오래된 분석은 결함 줄 앞뒤 일부(앞뒤 줄 수: {{limit:snapshot.excerpt_context_lines}})만 발췌해 보관합니다.
- 발췌본을 보여 줄 때는 "발췌본입니다" 안내가 나오고, 발췌 범위 밖은 볼 수 없습니다.
- 발췌도 남아 있지 않으면 "코드를 표시할 수 없습니다"와 이유가 나옵니다.

오래된 결함의 전체 코드를 다시 보고 싶으면 최신 코드를 다시 업로드해 분석하세요. 그 결함이 다시 감지되면 새 스냅샷으로 볼 수 있습니다.

## 과거 Run에서 보기

결함 상세에서 과거 Run을 고르면 그 Run 시점 이전에 결함이 마지막으로 존재한 때의 코드를 "Run N 시점의 코드"로 보여 줍니다. 그 Run과 이전 Run에 결함이 없었으면 보여 줄 코드가 없다고 안내합니다. Run에 대해서는 [히스토리](guide:history)를 보세요.

## 자주 묻는 점

- 결함 줄과 코드가 맞지 않아 보임: 코드 뷰어는 마지막 감지 시점의 코드를 보여 줍니다. 그 뒤에 코드를 고쳤다면 다시 업로드해 분석하세요.
- 규칙의 뜻이 궁금함: 결함 상세의 규칙 이름을 누르면 [규칙 설명](guide:rules)이 열립니다.
