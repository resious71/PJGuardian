## 무엇을 하나요

{{icon:nav.rules}} 메뉴는 서버가 분석에 쓰는 ruff(Python)와 ESLint(JavaScript/TypeScript) 규칙을 보여 줍니다. 결함이 왜 나왔는지, 규칙이 지금 분석에 쓰이는지, 도구 버전이 바뀌면서 무엇이 달라졌는지 확인할 때 씁니다.

- 기준은 서버가 지금 분석에 쓰는 도구 버전(활성 버전)입니다. 현재 버전은 ruff {{version:ruff}}, ESLint {{version:eslint}}입니다.
- 설명은 설치된 도구가 내놓는 정보 그대로입니다. 도구가 주지 않는 항목은 "{{ui:rules.no_description}}"으로 표시합니다.
- 규칙 설명은 번역하지 않습니다. 화면 언어를 영어로 바꿔도 도구의 원문 그대로 보입니다.

## 언어별 탭

목록 위에 두 탭이 있습니다.

- **{{ui:rules.tab.python}} · ruff**: Python 규칙
- **{{ui:rules.tab.javascript}} · ESLint**: JavaScript/TypeScript 규칙

탭 머리글에 그 도구의 전체 규칙 수가 함께 보입니다. 탭을 바꾸면 새 탭의 기본 조건으로 목록만 다시 불러옵니다. 마지막으로 본 탭은 이 브라우저에 기억되어 다음에 열 때 먼저 보입니다. 탭은 보기만 나눌 뿐이며, 프로젝트 언어에 따라 저절로 바뀌지 않습니다.

## 규칙 찾기

1. 탭을 고릅니다.
2. 검색 영역에 조건을 정합니다.
   - **검색**: 규칙 키·이름·설명의 일부(예: `F401`, `unused`)
   - **{{ui:rules.prefix_label}}**: 키가 이 글자로 시작하는 규칙만(예: `D`, `no-`)
   - 카테고리, {{ui:rules.col.severity}}(여러 개 고를 수 있음)
   - {{ui:rules.filter_analysis}}, {{ui:rules.filter_overridden}}, 자동 수정, 폐기 예정, {{ui:rules.filter_change}}
   - 정렬 기준과 순서
3. {{ui:defects.apply}} 단추를 누르거나 검색어 칸에서 Enter를 누릅니다.

조건을 바꾸기만 하고 검색하지 않으면 목록은 바뀌지 않고, 바뀐 조건이 있다는 표시가 나옵니다. {{ui:defects.clear_filters}}로 조건을 처음 상태로 되돌립니다. 적용한 조건은 주소에 남으므로 주소를 복사해 다른 사람과 같은 목록을 볼 수 있습니다.

목록의 열은 규칙, 요약, 카테고리, 기본 심각도, 분석 적용, 자동 수정, 상태입니다. 규칙을 누르면 상세 화면이 열립니다.

## 규칙 상세

상세 화면에는 다음이 나옵니다.

- **요약과 상태**: 안정, 미리보기(ruff preview), 폐기 예정, 삭제됨 중 하나. 폐기 예정이면 대체 규칙이 함께 보일 수 있습니다.
- **기본 심각도와 근거**: 분석에서 새로 생긴 결함에 처음 붙는 심각도입니다. 결함마다 사람이 바꿀 수 있고, 사람이 바꾼 값이 우선합니다.
- **{{ui:rules.analysis_title}}**: 이 규칙이 지금 분석에 쓰이는지(아래 "꺼진 규칙" 참고)
- **자동 수정 가능 여부**
- **{{ui:rules.description}}**: 도구가 준 설명과 예시. ESLint는 상세 설명을 주지 않아 "{{ui:rules.no_description}}"과 {{ui:rules.docs}} 링크가 보이고, ruff는 문서 주소를 주지 않아 링크가 없습니다.
- **{{ui:rules.history}}**: 아래 절 참고
- **{{ui:rules.defects_title}}**: 내가 볼 수 있는 프로젝트에 있는 이 규칙의 열린 결함 수와, 프로젝트별 결함 목록 링크

상세 위의 탭은 다른 언어의 목록으로 가는 링크입니다. "{{ui:rules.back_to_list}}"를 누르면 그 탭에서 마지막으로 검색한 조건의 목록으로 돌아갑니다.

## 버전별 변경 내역

서버에 적재된 도구 버전끼리 같은 규칙을 비교한 결과입니다. 버전마다 다음 변경이 표시됩니다.

- 신설, 삭제, 이름 변경(도구가 대체 규칙을 알려 준 경우만)
- 설명 변경(이전·이후 설명을 펼쳐 비교할 수 있음)
- 기본 활성, 기본 심각도, 자동 수정, 폐기 상태의 변경

가장 오래된 적재 버전은 기준 버전이라 그 이전과는 비교할 수 없습니다. 목록의 {{ui:rules.filter_change}} 조건으로 이번 버전에서 새로 생겼거나 바뀐 규칙만 볼 수 있습니다.

## 결함에서 규칙으로 가기

결함 목록의 규칙 열과 결함 상세의 규칙 이름은 규칙 설명으로 가는 링크입니다([결함 관리](guide:defects)).

- 예전 도구 버전에서 생긴 결함의 규칙이 지금 활성 버전에 없으면 "{{ui:rules.missing_short}}" 표시가 붙습니다. 규칙 설명에서는 마지막으로 있던 버전과, 이름이 바뀌었거나 삭제된 사실을 알려 줍니다.
- `syntax-error`(문법 오류)처럼 PJGuardian이 붙이는 특수 키는 도구 규칙이 아니어서 버전 내역이 없고, 앱이 결함을 기록하는 방식만 설명합니다.

## 꺼진 규칙

관리자는 규칙을 서버 전체에서 켜거나 끌 수 있습니다. 일반 사용자는 결과만 봅니다.

- 목록의 {{ui:rules.filter_analysis}} 열에 {{ui:rules.analysis_on}} 또는 {{ui:rules.analysis_off}}가 보입니다.
- 관리자가 기본값에서 바꾼 규칙에는 {{icon:ui.changed}} "{{ui:rules.overridden_badge}}" 표시가 붙습니다. 누가 왜 바꿨는지는 일반 사용자에게 보이지 않습니다.
- 바뀐 설정은 다음 분석부터 적용됩니다. 이미 끝난 Run의 결함은 바뀌지 않고, 끈 규칙의 열린 결함은 다음 분석에서 해결됨으로 바뀔 수 있습니다.
- Python 프로젝트가 ruff 설정 파일을 직접 올렸다면 그 프로젝트에는 관리자 변경이 적용되지 않습니다.

규칙을 켜거나 꺼야 한다고 생각되면 관리자에게 요청하세요.

## 주의

- 목록 위에 "규칙 데이터가 최신이 아닙니다"가 보이면 서버가 새 도구 버전의 규칙을 아직 불러오지 않은 것입니다. 잠시 뒤 다시 열어 보세요.
- 규칙 목록이 비어 있고 "규칙 데이터가 아직 없습니다"가 보이면 관리자에게 문의하세요.
- 규칙 목록은 Excel·CSV로 내보낼 수 있습니다. 지금 탭의 규칙만 내보냅니다([내보내기](guide:export)).
