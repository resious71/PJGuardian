## 무엇을 하는 화면인가요

**시스템 관리 > {{ui:backups.title}}**([/admin/backups](/admin/backups))에서 DB·설정·코드 스냅샷을 묶어 백업하고, 그 묶음으로 복원합니다. 웹 서버 없이 쓰는 명령줄(tools/backup.php, tools/restore.php)도 같은 기능을 합니다. 목적은 두 가지입니다.

- 운영 중 사고에 대비한 정기 백업
- 지금의 데이터와 설정을 **다른 PC로 옮기기**

백업·복원·리허설은 모두 워커가 실행합니다. 워커가 멈춰 있으면 화면 위에 경고가 나오고 아무것도 진행되지 않습니다.

## 백업 묶음에 들어가는 것

백업 묶음은 확장자가 .pjgbak인 zip 파일입니다. 이름은 만든 시각과 종류로 정해집니다(예: pjguardian-20261010-023000-daily.pjgbak).

- DB 전체(쓰기가 계속되는 중에도 한 시점의 일관된 사본)
- config.ini와 화면 설정(settings.local.ini) 사본 — **비밀번호·토큰·키 같은 민감 값은 비웁니다**
- bin 폴더 도구의 체크섬 목록(실행 파일은 넣지 않음)
- 코드 스냅샷(선택, 기본 포함)
- 항목별 크기와 SHA-256을 적은 목록(manifest)

**들어가지 않는 것**: secrets.ini(암호화 키·SMTP·LDAP 비밀번호), 업로드 원본, 작업 폴더, 로그. 저장소 자격 증명을 푸는 암호화 키는 "{{ui:icon.action.export_key}}"로 따로 보관합니다.

묶음에는 계정과 결함을 포함한 DB 전체가 들어 있습니다. 내려받거나 옮길 때 안전한 곳에 두세요.

## 백업하기

### 수동 백업

1. {{ui:icon.action.backup_now}}을 누릅니다. "{{ui:backups.snapshots_option}}"을 끄면 스냅샷 없이 더 작게 만듭니다.
2. 진행 표시(DB 복사 → 스냅샷 복사 → 묶음 만들기 → 검증)를 봅니다. 필요하면 {{ui:backups.job.cancel}}로 멈춥니다. 만들던 파일은 지웁니다.
3. 끝나면 목록에 종류 "{{ui:backups.kind.manual}}"로 나타나고, 요청한 관리자에게 백업 완료 알림이 갑니다.

백업은 만든 직후 구조·해시·DB 무결성·건수를 검증합니다. 검증에 실패하면 그 묶음을 지우고 실패로 기록합니다.

### 자동 백업

자동 백업은 **{{ui:config_settings.title}} > {{ui:config_settings.group.backup}}** 탭([/admin/config-settings#backup](/admin/config-settings#backup))에서 정합니다.

- 켜기/끄기, 주기(매일·매주·매월), 요일(매주일 때), 날짜(매월일 때, 1~31일 또는 말일), 실행 시각(지금 {{limit:backup.daily_at}}, 표시 시간대)을 고릅니다. 그 달에 없는 날짜면 그 달 마지막 날에 합니다.
- 워커가 30초마다 확인해 가장 최근 예정 시각 이후 자동 백업이 없으면 한 번 실행합니다. 워커가 오래 꺼져 있어 예정이 여러 번 지나갔어도 **한 번만** 합니다.
- 실패하면 10분 뒤 한 번 더 시도합니다. 그래도 실패하면 관리자 알림(백업 실패)을 보냅니다. 같은 사유는 1시간에 한 번만 알립니다.
- 주기를 바꾸면 바로 백업하지 않고 새 규칙의 **다음** 예정부터 따릅니다.
- 끄면 자동 백업, 재시도, 실패 알림, **자동 보관 정리**가 모두 멈춥니다. 수동 백업·복원·리허설은 그대로 됩니다.
- 목록에서 자동 백업은 종류 "{{ui:backups.kind.daily}}"로 보입니다.

### 백업 폴더

기본 백업 폴더는 프로젝트 바로 아래 backups입니다. 운영 데이터와 **같은 디스크**라서 디스크 고장 때 함께 잃습니다. 화면이 늘 경고하므로 운영에서는 별도 디스크나 네트워크 드라이브로 바꾸세요. 바꾸는 방법은 [설정 관리](guide:settings)의 경로 항목을 보세요. 폴더를 바꿔도 이전 묶음은 옮기지 않습니다.

백업 폴더에 .pjgbak 파일을 직접 복사해 넣어도 목록에 나타납니다. 큰 묶음은 이 방법이 편합니다.

## 보관 규칙

자동 백업이 성공한 뒤(자동 백업이 켜져 있을 때만) 오래된 묶음을 정리합니다.

- 자동·수동 백업은 {{limit:backup.retention_days}}일이 지나면 지웁니다. 단 최근 {{limit:backup.retention_min_count}}개는 오래돼도 남깁니다.
- 보관 개수 상한({{limit:backup.retention_max_count}}, 0이면 제한 없음)이 있으면 그보다 많은 오래된 묶음도 지웁니다.
- 복원 직전·업그레이드 직전 백업은 {{limit:backup.safety_retention_days}}일 동안 보관합니다.
- **마지막 성공 백업은 어떤 경우에도 남깁니다.** 검증 실패·검증 기록 없는 묶음은 자동으로 지우지 않습니다.
- 주기가 길면(매주·매월) 같은 기간에 남는 개수가 적습니다. 보관 기간을 늘리세요. 백업 탭 요약의 "{{ui:backups.sum.estimate}}"가 필요한 공간을 추정해 보여 줍니다.

마지막 백업이 오래되면(매일 기준 {{limit:backup.backup_stale_hours}}시간) 화면에 경고가 나옵니다.

## 암호화 키 내보내기

저장소 연동 자격 증명은 secrets.ini의 암호화 키로 암호화해 DB에 있습니다. 키는 묶음에 들어가지 않으므로, 다른 PC로 옮기거나 키를 잃을 때를 대비해 키 파일(.pjgkey)을 따로 받아 둡니다.

1. {{ui:icon.action.export_key}}를 누릅니다.
2. 관리자 비밀번호를 다시 입력하고, 암호문구(12자 이상)를 두 번 입력합니다.
3. 받은 .pjgkey 파일은 **백업 묶음과 다른 곳**에 보관합니다.

암호문구는 어디에도 저장하지 않습니다. **암호문구를 잃으면 키 파일을 열 수 없습니다.** 명령줄로 키를 내보내는 방법은 없습니다.

## 복원하기(화면)

1. 목록에서 복원할 묶음의 {{ui:icon.action.restore}}를 누릅니다. 다른 PC에서 만든 묶음은 먼저 "{{ui:backups.upload.title}}"로 올리고 {{ui:icon.action.verify}}을 통과시켜야 합니다(최대 {{limit:backup.upload_max_mb}}MB).
2. **사전 검증**: 묶음 구조·해시·DB 무결성·스키마를 확인합니다. 앱보다 새 스키마의 묶음은 거부합니다.
3. **미리보기**: 백업 시각·만든 PC·버전, 지금과 백업의 건수, 그리고 "이 시각 이후의 변경은 사라집니다"(이후 분석·결함 변경·계정 변경 건수)를 확인합니다.
4. **설정 복원(선택, 기본 꺼짐)**: 켜면 지금 값과 백업 값이 다른 항목이 나옵니다. 백업 폴더처럼 PC마다 다른 항목은 기본 해제입니다. secrets.ini는 절대 바꾸지 않습니다.
5. **암호화 키**: 지금 키로 백업의 자격 증명을 풀 수 있는지 보여 줍니다. 풀 수 없으면 "키 가져오기"로 .pjgkey와 암호문구를 넣습니다. 가져온 키로 실제로 풀어 본 뒤에만 키를 바꾸고, 지금 키는 이전 키로 보관합니다.
6. **진행 중인 작업**: 끝나기를 기다리거나(기본, 최대 {{limit:backup.restore_wait_max_minutes}}분) 진행 중인 분석을 취소하고 바로 복원합니다.
7. **확인**: 관리자 비밀번호와 확인 문구 "{{ui:backups.restore.confirm_word}}"를 입력하고 {{ui:backups.restore.submit}}을 누릅니다.

그러면 진행 상태 페이지(/restore-status)로 이동합니다. 워커가 다음 순서로 진행합니다.

1. 유지보수 모드에 들어가 새 작업을 받지 않습니다. 이때 다른 모든 화면은 진행 상태 페이지를 보여 줍니다.
2. **복원 직전 자동 백업**(종류 "{{ui:backups.kind.pre_restore}}")을 만듭니다. 이것이 실패하면 복원을 시작하지 않습니다. 복원을 되돌리고 싶으면 이 묶음으로 다시 복원합니다.
3. DB를 교체하고, 묶음에 스냅샷이 있으면 스냅샷 폴더도 교체합니다.
4. 묶음의 스키마가 앱보다 낮으면 마이그레이션합니다.
5. **모든 세션을 끊고**, 고른 설정과 가져온 키를 적용합니다.

중간에 실패하면 자동으로 원래 DB로 되돌립니다(상태 "{{ui:restore_status.status.rolled_back}}"). 되돌리기까지 실패하면 상태 페이지에 수동 복구 절차가 나옵니다. 그때는 웹 서버와 워커를 멈추고 안내대로 파일을 되돌린 뒤 다시 시작합니다.

## 명령줄로 백업·복원(다른 PC로 옮기기)

옛 PC에서 묶음을 만들고, 화면의 {{ui:icon.action.export_key}}로 .pjgkey를 받아 둡니다.

```
php tools/backup.php
php tools/backup.php --list
php tools/backup.php --verify
php tools/backup.php --kind=pre_upgrade
```

새 PC에서는 코드를 놓고 config.ini를 이 PC에 맞게 만든 뒤(키가 없으면 tools/make_secret_key.php로 만듦) 복원합니다. 워커가 돌고 있으면 명령줄 복원은 거부됩니다.

```
php tools/restore.php --file=<묶음 경로> --dry-run
php tools/restore.php --file=<묶음 경로> --check-bin
php tools/restore.php --file=<묶음 경로> --key=<키 파일> --with-config
php tools/worker.php
```

- `--dry-run`은 사전 검증과 미리보기만 합니다. 아무것도 바꾸지 않습니다.
- `--check-bin`은 묶음의 도구 체크섬과 이 PC의 bin 폴더를 비교합니다. 도구는 OS마다 따로 배치합니다.
- 암호문구는 프롬프트나 환경 변수 `PJG_KEY_PASSPHRASE`로만 받습니다. 명령줄 인자로 넣지 않습니다.
- 확인 문구 "복원" 입력은 `--yes`로 생략할 수 있습니다. 이때 설정 복원은 PC 고유가 아닌 항목만 적용합니다.
- 종료 코드는 성공 0, 실패·거부 1, 사용법·설정 오류 2입니다.
- 옮긴 뒤에는 옛 PC와 이동 매체에 남은 묶음·키 파일을 정리하세요.

## 복원 리허설

백업이 실제로 복원되는지 정기적으로 확인합니다. {{ui:icon.action.rehearse}}를 누르면 묶음(기본 최신)을 임시 폴더에 풀어 사전 검증, 마이그레이션 시험, 주요 조회를 실행합니다. **운영 데이터는 바뀌지 않습니다.**

마지막 리허설(없으면 첫 성공 백업)에서 {{limit:backup.rehearsal_interval_days}}일이 지나면 관리자 알림(복원 리허설 기한)과 화면 경고가 나옵니다. 명령줄은 `php tools/backup.php --rehearse`입니다.

## 복원 뒤 확인할 것

1. 모든 사용자가 다시 로그인해야 합니다. 사용자에게 미리 알리세요.
2. 진행 상태 페이지의 결과에서 "지금 키로 풀 수 없는 저장소 연동" 수를 봅니다. 있으면 키 파일을 가져와 다시 복원하거나, 프로젝트마다 연결 정보를 다시 입력합니다. 그동안 그 프로젝트의 주기 분석은 건너뜁니다.
3. 시스템 관리 > {{ui:admin_worker.title}}에서 워커가 실행 중인지 봅니다.
4. 프로젝트·결함 건수가 미리보기의 백업 건수와 맞는지 봅니다.
5. 설정을 복원했다면 [설정 관리](guide:settings)에서 값과 출처를 확인합니다.

## 문제 해결

- **"백업 폴더를 쓸 수 없어 백업하지 않습니다"**: 설정 관리 > 백업의 백업 폴더에서 {{ui:icon.action.check_path}}을 누릅니다. 웹 서버와 워커 계정의 쓰기 권한을 확인합니다.
- **자동 백업이 생기지 않음**: 자동 백업이 켜져 있는지, 워커가 실행 중인지, 요약의 "다음" 시각을 확인합니다.
- **백업이 디스크 문제로 거부됨**: 백업 폴더 디스크 사용률이 {{limit:disk.block_percent}} 이상이면 `backup_disk_full`, 여유가 부족하면 `backup_disk_low`입니다.
- **복원이 "요청됨"에서 멈춤**: 워커가 진행 중인 작업을 기다리는 중입니다. 워커가 꺼져 있으면 시작하거나 명령줄로 복원합니다.
- **복원이 끝났는데 모든 화면이 진행 상태 페이지임**: 유지보수 모드가 남은 것입니다. {{limit:backup.maintenance_stale_minutes}}분이 지나면 화면과 워커 로그가 경고합니다. 서버에서 `php tools/restore.php --leave-maintenance`로 끕니다.
- **마지막 성공 백업이 지워지지 않음**: 의도된 보호입니다(409).
- 비밀번호 재입력은 사용자당 분당 5회까지입니다.

운영 환경에서 확인할 것: Linux 서버와 네트워크 드라이브 백업 폴더에서 백업·복원과 권한.
