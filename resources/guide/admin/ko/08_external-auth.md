## 무엇을 하는 기능인가요

PJGuardian은 앱 계정(로컬) 외에 조직의 인증 시스템으로 로그인하는 방법 세 가지를 지원합니다. 셋 다 기본은 꺼져 있고, 시스템 관리 > 설정 관리의 각 탭에서 켭니다.

- **LDAP/AD** ([LDAP/AD 로그인](guide:auth-ldap)): 사용자는 로그인 화면의 ID·비밀번호 칸에 조직 계정과 비밀번호를 넣습니다. 서버가 디렉터리 서버에 직접 확인합니다. PHP ldap 확장이 필요합니다.
- **OIDC** ([SSO(OIDC) 로그인](guide:auth-oidc)): 로그인 화면의 SSO 단추를 누르면 조직의 로그인 서비스(IdP)로 이동했다 돌아옵니다. 제공자는 하나만 둘 수 있습니다.
- **SAML 2.0** ([SSO(SAML) 로그인](guide:auth-saml)): OIDC처럼 단추로 IdP에 갔다 옵니다. 앱에서 시작하는 로그인만 지원하고, IdP 포털에서 시작하는 로그인과 단일 로그아웃은 없습니다. IdP는 하나만 둘 수 있습니다.

여러 방식을 함께 켤 수 있습니다. OIDC와 SAML을 둘 다 켜면 로그인 화면에 단추가 둘 생깁니다. ID·비밀번호 칸은 늘 남아 있습니다.

## 모든 방식에 공통인 규칙

- **계정은 인증 방식을 하나만** 가집니다. 사용자 관리의 인증 방식 열에서 확인합니다.
- **로컬 계정은 외부 인증으로 로그인되지 않습니다.** 같은 로그인 ID의 디렉터리·IdP 계정이 있어도 로컬 계정을 빼앗거나 자동으로 바꾸지 않습니다. 바꾸려면 관리자가 **{{ui:users.action_auth_change}}**을 씁니다.
- **첫 로그인은 승인 대기 계정**이 됩니다. 승인 전에는 비활성이고 세션도 만들지 않습니다.
- **이름·이메일은 계정을 만들 때 한 번만** 외부 값으로 채웁니다. 이후 로그인에서 갱신하지 않으므로, 바뀌면 사용자 관리에서 고칩니다.
- **이메일이 같다는 이유로 기존 계정에 연결하지 않습니다.** 계정은 외부의 바뀌지 않는 식별자(LDAP은 안정 식별자 속성, OIDC는 발급자 + sub, SAML은 IdP EntityID + NameID 또는 지정한 속성)로 구분합니다.
- **주기 동기화는 없습니다.** 디렉터리·IdP에서 사람을 막아도 앱 계정은 그대로이니 퇴사자는 앱에서도 비활성화하세요.
- 디렉터리 검색 계정 비밀번호, OIDC 클라이언트 비밀, SAML SP 키는 설정 파일이 아니라 DB에 **암호화해 저장**하고 다시 보여 주지 않습니다(교체·삭제만). 암호화 키는 서버의 secrets.ini에 있고 백업에는 들어가지 않습니다. 키가 바뀌거나 없으면 화면에 "읽을 수 없음"이 나오니 다시 입력합니다.

## 승인 대기 흐름

1. 앱에 없는 사람이 외부 인증에 성공하면 승인 대기 계정이 만들어집니다(`user.pending_create`). 그 사람은 "{{ui:error.account_pending}}" 안내를 봅니다.
2. 관리자에게 앱 알림이 갑니다. 하루 5건까지는 한 건씩, 넘으면 그날은 요약 한 건입니다.
3. 관리자는 사용자 관리에서 보기를 **{{ui:users.approval_pending}}**으로 바꾸고 **{{ui:users.action_approve}}**(역할 선택), **{{ui:users.action_reject}}**, **{{ui:users.action_delete_pending}}** 중 하나를 합니다. 자세한 절차는 [계정 관리](guide:accounts)에 있습니다.
4. 승인되면 그 사람은 다음 로그인부터 바로 들어옵니다. 거절된 사람은 "{{ui:error.account_rejected}}" 안내를 봅니다.

승인 대기·거절 안내는 외부 인증(비밀번호 확인)을 **통과한 사람에게만** 나옵니다. 비밀번호가 틀리면 일반 실패 문구만 나오므로 계정이 있는지 드러나지 않습니다.

### 상한과 보관 기간

시스템 관리 > 설정 관리 > **{{ui:config_settings.group.auth}}** 탭에서 정합니다. 재시작 없이 바로 적용됩니다.

- **승인 대기 상한**(`auth.pending_max`, 지금 {{limit:auth.pending_max}}건): 승인 대기·거절 계정이 이만큼 있으면 새 요청을 받지 않습니다. 새로 오는 사람은 "{{ui:error.account_requests_closed}}" 안내를 보고, 관리자에게는 하루 한 번 상한 알림이 갑니다. 대기 목록을 정리하면 다시 받습니다.
- **승인 대기 보관 기간**(`auth.pending_retention_days`, 지금 {{limit:auth.pending_retention_days}}일): 이 기간 동안 상태가 바뀌지 않은 대기·거절 계정은 매일 정리 작업(`tools/cleanup.php`)이 지웁니다(`user.pending_purge`, 건수만 기록). 승인된 계정은 지우지 않습니다.

### 관리자가 미리 만든 외부 계정

[계정 CSV 일괄 처리](guide:account-csv)(`auth_type`에 외부 방식)나 **{{ui:users.action_auth_change}}**으로 만든 외부 계정은 승인된 상태이며 승인 대기를 거치지 않습니다. 그 사람의 첫 외부 로그인 때 로그인 ID가 같은 외부 계정과 연결됩니다(`user.external_link`). 이후에는 외부 식별자로 확인하므로, 디렉터리에서 같은 ID를 다른 사람에게 다시 주면 로그인을 거부하고 관리자에게 "외부 신원 불일치" 알림을 보냅니다.

## 인증 방식 전환

외부 방식이 켜져 있으면 사용자 관리 각 행에 **{{ui:users.action_auth_change}}**이 생깁니다.

- 로컬 → 외부: 앱 비밀번호가 지워지고 다음 외부 로그인 때 연결됩니다.
- 외부 → 로컬: 임시 비밀번호를 한 번 보여 줍니다({{limit:auth.temp_password_expiry}} 유효).
- 자기 자신과 마지막 활성 로컬 관리자는 바꿀 수 없습니다.
- 대상은 즉시 로그아웃되고 `user.auth_type_change`가 남습니다.

외부 방식을 꺼도 그 방식의 계정은 남지만 로그인할 수 없습니다. 다시 켜면 그대로 로그인됩니다.

## 로컬 관리자 비상 로그인

디렉터리 서버나 IdP에 장애가 나면 그 방식의 로그인만 안 됩니다. **로컬 관리자는 로그인 화면의 ID·비밀번호 칸으로 늘 로그인할 수 있습니다.**

- 활성 로컬 관리자는 늘 한 명 이상 남도록 앱이 막습니다(비활성화·강등·인증 방식 전환 모두).
- 운영에서는 로컬 관리자를 두 명 이상 두고, 비밀번호를 안전한 곳에 보관하세요.
- 로컬 관리자도 들어올 수 없으면 서버에서 `php tools/user_cli.php`로 잠금을 풀거나 임시 비밀번호를 발급합니다([계정 관리](guide:accounts)).

## 공통 문제 해결

로그인 실패의 자세한 이유는 화면에 나오지 않습니다(계정 존재 여부를 숨기기 위해). 이유는 감사 로그의 `auth.login_failed`에 사유 코드로만 남습니다. 사유는 [감사 로그](guide:audit-log) 화면에서 작업 `auth.login_failed`로 골라 볼 수 있습니다.

### SSO 오류 코드

SSO(OIDC·SAML) 실패는 로그인 화면에 "SSO 로그인에 실패했습니다"와 코드가 나옵니다.

- **E-SSO-STATE**: 로그인 요청을 확인하지 못함 — 오래된 요청(10분), 재사용, 다른 브라우저, SAML의 IdP 시작 로그인. 사용자에게 로그인 화면에서 단추를 새로 누르게 합니다. IdP 포털의 앱 타일로 들어오는 습관이 있으면 안내가 필요합니다.
- **E-SSO-IDP**: IdP가 오류를 돌려줌(동의 거부, 이 앱을 쓸 권한 없음 등). IdP의 앱 할당을 확인합니다.
- **E-SSO-TOKEN**: 응답 검증 실패 — 서명, 시간, 대상(audience), 발급자 불일치. 서버 시계, IdP 인증서·키, 설정 값을 확인합니다.
- **E-SSO-CONFIG**: 앱 설정이 덜 됐거나 비밀·키가 없거나 읽을 수 없음. 설정 탭의 연결 시험·설정 확인을 돌립니다.
- **E-SSO-UNAVAILABLE**: IdP에 닿지 않음·시간 초과. 방화벽·프록시·DNS를 확인합니다.
- **E-SSO-RATE**: 로그인 시작 요청이 너무 많거나 그 IP가 로그인 실패로 잠시 막힘. 기다리면 풀립니다.
- **E-SSO-DENIED**: 외부 인증은 통과했지만 계정을 정하지 못함 — 같은 로그인 ID의 다른 계정(로컬·LDAP·다른 식별자)이 있음, 계정이 비활성, 로그인 ID 형식이 맞지 않음.

### 자주 만나는 경우

- **같은 로그인 ID의 로컬 계정이 있어 SSO가 거부됨**(E-SSO-DENIED, 관리자 알림): 같은 사람이면 그 로컬 계정을 **{{ui:users.action_auth_change}}**으로 외부 방식으로 바꿉니다. 다음 로그인 때 연결됩니다. 다른 사람이면 IdP 쪽 로그인 ID를 조정해야 합니다.
- **LDAP 로그인에 "{{ui:error.auth_service_unavailable}}"**: 디렉터리 서버에 닿지 않습니다. 시스템 관리 > [점검](/admin/checks) 화면과 LDAP/AD 탭의 연결 시험으로 원인을 봅니다.
- **"읽을 수 없음" 표시**: 서버의 암호화 키가 바뀌었거나 없습니다. 비밀번호·비밀을 다시 저장하거나 SP 키를 다시 만듭니다.
- **설정 탭에 마이그레이션 안내가 나옴**: 서버에서 `php tools/migrate.php`를 실행합니다. 적용 전에는 그 방식이 꺼진 것처럼 동작합니다.
