## 무엇을 하는 화면인가요

![사용자 관리 화면의 사용자 목록. 검색 칸과 역할·상태·계정 종류 선택, 검색 단추 아래에 로그인 ID·표시 이름·이메일·역할·상태·인증 방식·소속 그룹·계정 상태·작업 열이 있고, 행마다 정보 수정·역할 변경·비활성화·비밀번호 변경·임시 비밀번호 발급 단추가 있습니다(가짜 계정).](guide-img:admin-users)

관리자 메뉴의 **사용자 관리**([/admin/users](/admin/users))에서 PJGuardian 계정을 만들고 관리합니다. 이 화면과 API는 관리자만 쓸 수 있습니다. 그룹 관리자도 이 화면에는 들어올 수 없습니다(그룹 관리자의 계정 만들기는 [그룹과 프로젝트 접근](guide:groups-access)).

화면은 위의 **사용자 추가** 영역과 아래의 **사용자 목록**으로 나뉩니다. 목록 위에는 검색 칸(로그인 ID·이름·이메일)과 역할·상태·보기 선택이 있습니다. 보기는 **계정**(기본), **{{ui:users.approval_pending}}**, **{{ui:users.approval_rejected}}** 셋입니다.

목록의 열은 로그인 ID, 표시 이름, 이메일, 역할, 상태, 인증 방식, 소속 그룹, 계정 상태, 작업입니다.

- **인증 방식**: {{ui:account.auth_local}}, {{ui:account.auth_ldap}}, {{ui:account.auth_oidc}}, {{ui:account.auth_saml}} 중 하나입니다. 계정은 인증 방식을 하나만 가집니다.
- **소속 그룹**: 읽기 전용입니다. 바꾸려면 그룹 화면을 씁니다.
- **계정 상태**: 정상, 잠김(언제까지), 임시 비밀번호(언제까지 유효), 비밀번호 변경 필요, 외부 인증 계정의 "첫 로그인 전(외부 신원 미연결)", 승인 대기 계정의 요청 시각을 보여 줍니다.

계정은 지우지 않고 비활성화만 합니다. 예외는 한 번도 승인된 적 없는 승인 대기·거절 계정뿐입니다.

## 계정 추가

1. **사용자 추가** 영역에 로그인 ID, 표시 이름, 이메일(선택), 역할을 넣습니다.
2. **{{ui:users.create_submit}}**을 누릅니다.
3. 나타나는 대화상자에서 임시 비밀번호를 복사해 본인에게 안전하게 전달합니다. 이 값은 대화상자를 닫으면 다시 볼 수 없고 서버도 평문을 보관하지 않습니다.

- 로그인 ID는 영문·숫자로 시작하고 영문·숫자·`.` `_` `@` `-`만 쓸 수 있습니다(100자 이하). 대소문자만 다른 같은 ID는 만들 수 없고, 한 번 정하면 바꿀 수 없습니다.
- 표시 이름은 1~100자이며, 다른 사용자의 로그인 ID와 같은 이름은 쓸 수 없습니다(사칭 방지).
- 임시 비밀번호는 {{limit:auth.temp_password_expiry}} 동안 유효하고 첫 로그인 때 새 비밀번호로 바꿔야 합니다.
- 이 화면은 앱 계정(로컬)만 만듭니다. 외부 인증 계정을 미리 만들려면 [계정 CSV 일괄 처리](guide:account-csv)나 아래의 인증 방식 변경을 씁니다.
- 감사 로그 작업 이름은 `user.create`입니다.

여러 계정을 한꺼번에 만들려면 화면 위의 **{{ui:account_import.open}}**을 누릅니다.

## 정보 수정

행의 **{{ui:users.action_edit}}**으로 표시 이름과 이메일을 고칩니다. 로그인 ID는 바꾸지 않습니다.

- 외부 인증(LDAP/AD·SSO) 계정도 앱에서 고칩니다. 외부 값은 계정을 만들 때 한 번만 가져오고 이후 로그인에서 덮어쓰지 않으므로, 디렉터리에서 이름이 바뀌었으면 여기서 직접 고쳐야 합니다.
- 입력 오류는 해당 칸 바로 아래에 나옵니다.
- 사용자는 자기 정보를 **내 정보**에서 고칠 수 있습니다. 관리자는 모든 사용자의 정보를 고칠 수 있습니다.
- 감사 로그(`user.update`)에는 바뀐 항목이 남고 이메일은 가려서 기록합니다.

## 역할 변경과 비활성화

- **{{ui:users.action_promote}}** / **{{ui:users.action_demote}}**: 확인 대화상자 뒤에 바뀝니다. 대상은 즉시 로그아웃되고 다시 로그인해야 합니다(`user.role_change`).
- **{{ui:users.action_deactivate}}**: 대상은 즉시 로그아웃되고 더 이상 로그인할 수 없습니다. 계정과 기록(담당 결함, 이력)은 그대로 남습니다(`user.deactivate`).
- **{{ui:users.action_activate}}**: 비활성 계정을 다시 쓸 수 있게 합니다(`user.activate`).

비활성 사용자가 담당자였던 결함은 담당자가 그대로 남고 화면에 "비활성" 꼬리표가 붙습니다. 새로 담당자로 지정할 수는 없습니다.

### 마지막 관리자 보호

다음 두 조건은 늘 지켜집니다.

- 활성 관리자가 한 명 이상
- 활성 **로컬(앱 계정)** 관리자가 한 명 이상 — 디렉터리나 IdP에 장애가 나도 앱 비밀번호로 들어올 수 있게 하기 위해서입니다.

이를 깨는 비활성화, 일반 사용자로 변경, 인증 방식 변경(로컬 → 외부)은 서버가 거부합니다(`last_admin`). 단추는 보이지만 누르면 오류 알림이 나옵니다. 운영에서는 로컬 관리자를 두 명 이상 두는 것을 권장합니다.

## 비밀번호: 임시 비밀번호와 직접 지정

앱 계정(로컬)에만 있는 동작입니다. 외부 인증 계정의 비밀번호는 조직의 디렉터리·IdP에서 관리합니다.

- **{{ui:users.action_temp}}**: 지금 비밀번호가 바로 무효가 되고 대상은 로그아웃됩니다. 잠금도 함께 풀립니다. 임시 비밀번호는 다음 대화상자에서 한 번만 보이며 {{limit:auth.temp_password_expiry}} 동안 유효하고, 첫 로그인 때 변경해야 합니다(`user.temp_password`).
- **{{ui:users.action_set_password}}**: 관리자가 새 비밀번호를 정합니다. 비밀번호 정책이 그대로 적용되고, 대상은 즉시 로그아웃됩니다. 다시 바꾸라고 강제하지 않으며, 대상은 다음 로그인 때 "관리자가 비밀번호를 변경했다"는 안내를 한 번 봅니다(`user.password_set`). 자기 비밀번호는 이 단추로 바꿀 수 없고 비밀번호 변경 화면에서 바꿉니다.

비밀번호 값은 감사 로그·로그 어디에도 남지 않습니다. 전달은 메신저 기록이 남지 않는 방법처럼 안전한 경로를 쓰세요.

## 잠금 해제

앱 계정은 로그인에 {{limit:auth.lockout_max_failures}}번 연속 실패하면 {{limit:auth.lockout_duration}} 동안 잠깁니다. 잠긴 계정은 계정 상태 열에 "잠김"이 보이고 **{{ui:users.action_unlock}}** 단추가 생깁니다.

1. **{{ui:users.action_unlock}}**을 누릅니다.
2. 확인 대화상자에서 다시 누르면 실패 횟수가 초기화되고 바로 로그인할 수 있습니다(`user.unlock`).

LDAP/AD 계정은 앱이 잠그지 않고 디렉터리의 잠금 정책을 따릅니다.

### 관리자가 화면에 들어올 수 없을 때

모든 관리자가 잠겼거나 비밀번호를 잃었으면 서버에서 계정 복구 명령을 씁니다. 감사 로그에 행위자 "cli"로 남습니다.

```
php tools/user_cli.php status <로그인 ID>
php tools/user_cli.php unlock <로그인 ID>
php tools/user_cli.php reset-password <로그인 ID>
```

- `status`: 역할, 상태, 인증 방식, 잠금, 임시 비밀번호 여부를 봅니다.
- `unlock`: 잠금을 풉니다.
- `reset-password`: 임시 비밀번호를 발급해 화면에 한 번만 출력합니다. 잠금도 풀리고 그 사용자의 세션은 모두 끊깁니다. 앱 계정(로컬)에만 쓸 수 있습니다.

## 승인 대기 계정

외부 인증(LDAP/AD·OIDC·SAML)으로 처음 로그인한 사람은 **승인 대기 계정**이 됩니다. 승인 전에는 비활성이고 아무 권한이 없습니다. 대기 계정이 있으면 계정 보기 위에 "승인 대기 계정 N건" 안내와 **{{ui:users.pending_show}}** 단추가 나옵니다. 관리자에게는 앱 알림도 갑니다.

1. 보기를 **{{ui:users.approval_pending}}**으로 바꿉니다(또는 안내의 **{{ui:users.pending_show}}**).
2. 로그인 ID, 이름, 이메일, 인증 방식, 요청 시각을 확인합니다. 이름 옆에 **{{ui:users.name_conflict}}** 꼬리표가 있으면 표시 이름이 다른 사용자의 로그인 ID와 같다는 뜻입니다. 먼저 **{{ui:users.action_edit}}**으로 이름을 고치세요.
3. **{{ui:users.action_approve}}**를 누르고 역할을 고릅니다(기본 일반 사용자). 관리자로 승인하면 확인 대화상자가 한 번 더 나옵니다. 승인하면 바로 로그인할 수 있습니다(`user.approve`).
4. 받아들이지 않을 요청은 **{{ui:users.action_reject}}**합니다(`user.reject`). 거절한 계정은 남아 있어 같은 사람이 다시 로그인해도 요청이 늘지 않습니다. 나중에 승인할 수도 있습니다.
5. **{{ui:users.action_delete_pending}}**는 승인된 적 없는 요청만 지웁니다(`user.pending_delete`). 같은 사람이 다시 로그인하면 새 요청이 생깁니다.

- 일괄 승인은 없습니다. 다른 관리자가 먼저 처리했으면 `approval_conflict` 오류가 나오니 목록을 다시 불러오세요.
- 승인되지 않은 계정에는 역할 변경·활성화를 할 수 없습니다(`account_not_approved`).
- 대기 계정 수 상한과 보관 기간은 [외부 인증 개요](guide:external-auth)에서 설명합니다.

## 인증 방식 변경

외부 인증 방식이 하나라도 켜져 있으면 각 행(자기 자신 제외)에 **{{ui:users.action_auth_change}}**이 생깁니다. 대상은 바로 로그아웃됩니다(`user.auth_type_change`).

- **로컬 → 외부**: 앱 비밀번호, 임시 비밀번호, 잠금 정보가 지워집니다. 다음 외부 로그인 때 로그인 ID가 같은 외부 계정과 연결됩니다. 이렇게 관리자가 바꾼 계정은 승인 대기를 거치지 않습니다.
- **외부 → 로컬**: 임시 비밀번호를 한 번만 보여 줍니다({{limit:auth.temp_password_expiry}} 유효, 첫 로그인 때 변경).
- 자기 자신은 바꿀 수 없고(`self_auth_type_change`), 마지막 활성 로컬 관리자도 외부로 바꿀 수 없습니다(`last_admin`).

## 문제 해결

- **"마지막 활성 관리자는…" 오류**: 다른 로컬 관리자를 먼저 만들거나 활성화한 뒤 다시 시도합니다.
- **임시 비밀번호를 놓쳤음**: 다시 **{{ui:users.action_temp}}**을 누르면 새 값이 발급되고 이전 값은 무효가 됩니다.
- **임시 비밀번호가 만료됨**: 사용자가 로그인할 수 없습니다. 새로 발급합니다.
- **외부 인증 사용자가 비밀번호를 바꿔 달라고 함**: 앱에서 바꿀 수 없습니다. 조직의 디렉터리·IdP 관리자에게 안내합니다.
- **퇴사자 처리**: 외부 인증 계정이라도 디렉터리에서 막는 것만으로는 앱 계정이 비활성화되지 않습니다(주기 동기화 없음). 앱에서도 **{{ui:users.action_deactivate}}**하세요.
