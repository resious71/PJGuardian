## 무엇을 하는 화면인가

프로젝트는 분석 대상 코드를 묶는 단위입니다. 프로젝트를 만들고, 고치고, 지우는 일은 관리자만 합니다.

- {{icon:admin.projects}} {{ui:icon.admin.projects}}를 누르면 프로젝트 목록이 열립니다. 관리자에게는 모든 프로젝트와 접근 범위(관리자만, 또는 연결된 그룹·사용자 수)가 보입니다.
- 프로젝트 상세 화면 위쪽에 {{ui:projects.edit_button}}과 {{ui:projects.delete_button}}가 있습니다. 일반 사용자에게는 이 단추가 보이지 않습니다.
- 과거 Run의 상세(과거 Run 보기)는 오래된 것부터 자동으로 정리되고, {{ui:icon.admin.tools}} > {{ui:admin_runs.title}}에서 직접 지울 수도 있습니다.

## 프로젝트 만들기

1. 프로젝트 목록에서 {{ui:projects.new_button}}를 누릅니다.
2. {{ui:projects.field_name}}을 입력합니다. 1~100자이고 줄바꿈 같은 제어 문자는 쓸 수 없습니다. 대소문자만 다른 같은 이름은 만들 수 없습니다.
3. {{ui:projects.field_language}}를 고릅니다. Python이면 ruff, JavaScript/TypeScript면 ESLint로 분석합니다. 언어는 만든 뒤에 바꿀 수 없습니다.
4. 필요하면 {{ui:projects.field_description}}을 입력합니다(2,000자 이하).
5. {{ui:projects.create_submit}}를 누릅니다.

만든 직후의 프로젝트는 아무에게도 연결되지 않아 관리자만 볼 수 있습니다. 이어서 다음을 설정합니다.

- 접근 범위: 수정 화면의 {{ui:access.title}}에서 그룹·사용자를 연결합니다. [그룹과 프로젝트 접근 범위](guide:groups-access)를 보세요.
- 분석 제외 패턴: 수정 화면에서 한 줄에 패턴 하나씩 더합니다. 서버 기본 제외 목록은 늘 적용되며 여기서 바꿀 수 없습니다.
- 소스 저장소와 주기 분석: [소스 저장소 연동](guide:repository), [주기 분석](guide:schedule)을 보세요.

## 프로젝트 고치기

프로젝트 상세에서 {{ui:projects.edit_button}}을 누르면 이름, 설명, 제외 패턴, 접근 범위, 소스 저장소, 주기 분석을 한 화면에서 고칩니다. 이름·설명·제외 패턴은 {{ui:projects.save_submit}}으로 저장하고, 저장소와 주기 분석은 각 구역의 단추로 따로 저장합니다.

- 제외 패턴은 분석 루트 기준 상대 경로와 비교합니다. `*`, `?`, `**`를 쓸 수 있고, 앞에 `/`가 있으면 루트 기준, 끝에 `/`가 있으면 폴더에만 맞습니다.
- 빈 패턴, `.`·`..` 조각, 절대 경로, 역슬래시, 대괄호·중괄호·느낌표 문법은 저장할 수 없습니다.
- 제외 패턴을 바꾸면 다음 분석부터 반영됩니다. 새로 제외된 파일의 결함은 삭제된 파일과 달리 자동으로 해결되지 않고 상태를 유지합니다.

## 프로젝트 삭제

### 절차

1. 프로젝트 상세에서 {{ui:projects.delete_button}}를 누릅니다.
2. 삭제 화면에서 함께 지워질 것의 건수를 확인합니다.
3. 확인을 위해 프로젝트 이름을 정확히 입력합니다. 대소문자와 공백까지 같아야 {{ui:projects.delete_submit}} 단추가 켜집니다.
4. {{ui:projects.delete_submit}}를 누르면 즉시 지우고 프로젝트 목록으로 돌아갑니다.

### 함께 지워지는 것

삭제는 되돌릴 수 없습니다. 다음이 모두 지워집니다.

- 분석 이력과 Run 기록
- 결함과 결함 변경 이력
- 코드 스냅샷 파일
- 업로드 기록(남아 있는 조각·작업 파일 포함)
- 접근 매핑(그룹과 사용자 계정 자체는 남습니다)
- 소스 저장소 연결과 저장된 자격 증명, 주기 분석 설정

감사 로그에는 삭제 기록(`project.delete`)이 이름, 언어, 분석·결함 수와 함께 남습니다. 지운 프로젝트를 되살리려면 삭제 전 시점의 백업으로 서버 전체를 복원하는 방법밖에 없습니다. 중요한 프로젝트라면 삭제 전에 [백업과 복원](guide:backup-restore)에서 백업이 있는지 확인하세요.

### 삭제가 막히는 경우

그 프로젝트에 대기·실행 중인 분석이 있거나, 워커가 업로드를 조립·해제하고 있으면 삭제할 수 없다는 안내가 나옵니다. 분석이 끝나거나 취소한 뒤 다시 시도하세요. 주기 분석이 곧 실행될 프로젝트라면 먼저 주기 분석을 끄는 편이 안전합니다.

DB에서 지운 뒤 파일 삭제에 실패한 항목은 정리 대상 목록에 남고, 정리 작업이 다시 지웁니다. 남은 항목 수는 {{ui:admin_checks.title}} 탭의 정리 작업 구역에서 볼 수 있습니다.

## Run 상세 보관

Run마다 결함 현황, Run별 상세, 결함 상세·코드를 그 시점으로 볼 수 있습니다(과거 Run 보기). 오래된 Run의 이 상세는 자동으로 정리됩니다.

- 프로젝트마다 최근 {{limit:runs.detail_keep}}개 Run의 상세를 남깁니다. 0이면 자동 정리를 하지 않습니다. 1이나 2는 설정할 수 없습니다.
- 정리는 워커가 성공한 분석을 반영한 뒤에 합니다. 한 번에 최대 {{limit:runs.retention_batch}}개씩, 남으면 다음 성공 분석 때 이어서 합니다. 실패·취소한 분석 뒤에는 하지 않습니다.
- 가장 최근 Run은 언제나 남습니다.
- 보관 개수는 {{ui:config_settings.title}} > {{ui:config_settings.group.retention}} 탭에서 바꿉니다. 이미 지운 Run은 개수를 늘려도 되살아나지 않습니다.

### 지운 뒤에 남는 것

- 남는 것: Run 번호, 날짜, 건수(감지·신규·해결·재오픈·유지·열린 결함), 도구 버전, 히스토리 표, 대시보드 추이, 결함과 결함 이력
- 볼 수 없는 것: 그 Run 시점의 결함 목록·상세·코드. 주소로 열면 "Run N의 상세는 삭제되었습니다" 안내와 최신 Run으로 가는 링크가 나옵니다. Run 선택기에는 "상세 삭제됨"으로 보이고 고를 수 없습니다.

상세 삭제는 표시만 바꾸므로 DB 파일 크기는 거의 줄지 않습니다. 디스크 공간을 줄이려는 목적이라면 [보존 기간과 디스크](guide:retention-disk)를 보세요.

## Run 상세 수동 삭제

1. {{ui:icon.admin.tools}} > {{ui:admin_runs.title}} 탭을 엽니다.
2. 프로젝트를 고릅니다. Run 목록이 최신순으로 보이고, 각 Run의 상세 상태(상세 있음, 수동 삭제됨, 자동 삭제됨)가 함께 보입니다.
3. 지울 Run의 체크박스를 고릅니다. 쪽을 넘겨도 선택이 유지됩니다. 최근 몇 개를 빼고 모두 고르려면 개수를 정하고 {{ui:admin_runs.select_old}}을 누릅니다.
4. {{ui:admin_runs.delete}}를 누릅니다.
5. 확인 창에서 대상 Run 목록을 확인하고 프로젝트 이름을 정확히 입력한 뒤 확인합니다.

- 가장 최근 Run과 이미 지운 Run은 고를 수 없습니다.
- 결과로 지운 Run 수와 이미 지워져 건너뛴 Run이 보이고, 감사 로그(`run.detail_delete`)가 남습니다.
- 그 사이 새 분석이 끝나 고른 Run이 최신이 되면 아무것도 지우지 않고 거부합니다. 목록을 새로 고친 뒤 다시 고르세요.

## 문제 해결

- 같은 이름이 이미 있다는 오류: 대소문자를 구분하지 않으므로 대소문자만 다른 이름도 중복입니다.
- 삭제 단추가 켜지지 않음: 입력한 이름이 앞뒤 공백까지 정확히 같아야 합니다.
- 과거 Run 화면이 "상세는 삭제되었습니다"로 나옴: 자동 보관 또는 수동 삭제로 지운 Run입니다. 히스토리 표의 건수는 그대로 볼 수 있습니다.
