## 무엇을 하는 기능인가

ruff와 ESLint는 서버 기본 설정 파일에 정한 규칙으로 분석합니다. 관리자는 그 위에 규칙별로 켜기·끄기를 얹을 수 있습니다. 서버 기본 설정 파일은 그대로 두고 바꾼 것만 따로 저장합니다.

- 규칙을 켜고 끄는 곳: {{icon:nav.rules}} {{ui:icon.nav.rules}} 화면의 규칙 상세, 규칙 목록의 스위치와 일괄 변경
- 바꾼 규칙을 모아 보고 되돌리는 곳: {{ui:icon.admin.tools}} > {{ui:admin_rule_settings.title}}
- 규칙마다 정해진 기본 심각도: 새로 감지한 결함에 자동으로 붙는 심각도

### 적용 범위와 시점

- ESLint: 모든 JavaScript/TypeScript 프로젝트에 적용됩니다. 업로드한 ESLint 설정은 어차피 쓰지 않습니다.
- ruff: 서버 기본 설정으로 분석하는 프로젝트에만 적용됩니다. 업로드한 소스에 ruff 설정 파일이 있는 프로젝트는 그 설정을 쓰므로 관리자 변경이 반영되지 않습니다.
- 변경은 다음 분석부터 반영됩니다. 분석은 시작할 때 한 번 읽어 고정하므로, 대기 중인 분석에는 반영되고 이미 실행 중인 분석은 그대로입니다.
- 이미 끝난 Run의 결함은 바뀌지 않습니다. 끈 규칙의 열린 결함은 다음 분석에서 감지되지 않아 해결됨으로 처리될 수 있습니다.

## 규칙 하나 켜기·끄기

1. {{ui:icon.nav.rules}}에서 도구 탭(Python · ruff 또는 JavaScript/TypeScript · ESLint)을 고르고 규칙을 찾아 엽니다.
2. 규칙 상세의 {{ui:rules.col.analysis}} 구역에서 {{ui:rules.enable}} 또는 {{ui:rules.disable}}를 누릅니다. 이미 바꾼 규칙이면 {{ui:rules.reset_default}}도 보입니다.
3. 확인 창에서 변경 내용, 서버 전체에서 이 규칙의 열린 결함 수를 확인합니다. 필요하면 사유(200자까지)를 적습니다.
4. 확인합니다. "다음 분석부터 반영됩니다"가 보이면 끝입니다.

관리자는 규칙 상세에서 마지막 변경 시각·변경자·사유를 볼 수 있습니다. 일반 사용자에게는 적용 중·꺼짐과 관리자 변경 여부만 보입니다.

### 켤 수 없는 규칙

다음 규칙은 켜기 단추가 꺼지고 이유가 보입니다. 끄기는 언제나 됩니다.

- 도구에서 삭제된 규칙, 폐기 예정 규칙
- ruff의 미리보기(preview) 규칙
- 타입 정보가 필요한 ESLint 규칙
- 옵션 없이는 아무것도 검사하지 않는 규칙
- 앱이 붙인 특수 키(`syntax-error` 등)

ruff에서 서로 맞지 않는 규칙 쌍(D203과 D211, D212와 D213)을 함께 켜면 ruff가 한쪽(D203, D213)을 스스로 끕니다. 화면에는 적용 중으로 보여도 분석 결과에 나오지 않으므로 함께 켜지 마세요.

## 목록에서 바꾸기와 일괄 변경

규칙 목록의 {{ui:rules.col.analysis}} 칸에는 관리자에게 스위치가 보입니다. 스위치를 누르면 상세와 같은 확인 창이 뜨고, 그 행만 바뀝니다(쪽·검색 조건·스크롤 위치는 그대로).

여러 규칙을 한꺼번에 바꾸려면 다음 순서로 합니다.

1. 검색 조건으로 대상을 좁힙니다. {{ui:rules.filter_analysis}}(전체·적용 중·꺼짐), {{ui:rules.filter_overridden}}(변경된 것만), 규칙 키 접두사 등을 씁니다.
2. 행 앞 체크박스로 고르거나, 머리글 체크박스로 이 쪽 전체를 고릅니다. 결과가 더 있으면 "검색 결과 전체 M개 선택"으로 마지막에 검색한 조건의 결과 전체를 고를 수 있습니다.
3. 아래 막대에서 {{ui:rules.bulk_enable}}, {{ui:rules.bulk_disable}}, {{ui:rules.bulk_reset}} 중 하나를 누릅니다.
4. 미리보기에서 실제로 바뀔 수, 이미 그 상태라 그대로인 수, 이유별 건너뛸 수, 예시를 확인합니다.
5. 검색 결과 전체를 골랐거나 20개를 넘으면 도구 이름(ruff 또는 eslint)을 입력해야 확인 단추가 켜집니다.
6. 확인하면 바꾼 수와 건너뛴 수가 보입니다.

- 한 번에 {{limit:rules.bulk_max}}개까지 바꿀 수 있습니다. 넘으면 잘라서 적용하지 않고 거부하므로 검색 조건을 더 좁히세요.
- 켤 수 없는 규칙은 일괄 변경에서 오류 대신 건너뜀으로 셉니다.
- 예: ruff 탭에서 규칙 키 접두사 `D`와 분석 적용 "꺼짐"으로 검색 → 이 쪽 전체 선택 → 검색 결과 전체 선택 → {{ui:rules.bulk_enable}}를 하면 docstring 규칙을 한꺼번에 켭니다. 되돌릴 때는 관리자 변경 "변경된 것만"으로 검색해 전체를 고른 뒤 {{ui:rules.bulk_reset}}를 누릅니다.

## 규칙 설정 탭

{{ui:icon.admin.tools}} > {{ui:admin_rule_settings.title}}(/admin/rule-settings)에서 관리자가 바꾼 규칙 전체를 봅니다.

- 요약: 도구별로 켠 수·끈 수, 마지막 변경, 실효 설정 해시 앞자리, ruff 설정을 업로드해 관리자 변경이 적용되지 않는 프로젝트 수
- 도구·상태로 거르기
- 표: 규칙, 이름, 변경 내용, 기본값, 사유, 변경자, 변경 시각, 상태, 되돌리기 단추
- 상태가 {{ui:admin_rule_settings.state.missing}} 또는 {{ui:admin_rule_settings.state.not_enableable}}이면, 도구 버전이 바뀌어 그 변경을 지금 분석에 적용하지 못하는 것입니다. 되돌리거나 새 버전에 맞게 다시 정하세요.

### 되돌리기

- 한 건: 행의 되돌리기 단추를 누릅니다. 그 규칙은 서버 기본 설정의 값으로 돌아갑니다.
- 도구 전체: {{ui:admin_rule_settings.reset_all}}를 누르고 도구 이름을 입력합니다. 한 번에 {{limit:rules.override_reset_max}}건까지 되돌리며, 남으면 남은 건수를 알려 줍니다. 다시 누르면 이어서 되돌립니다.

변경과 되돌리기는 감사 로그(`rules.override_set`, `rules.override_clear`, `rules.override_bulk`, `rules.override_reset_all`)에 남습니다.

## 개정 번호와 충돌

도구마다 규칙 변경의 개정 번호가 있고, 켜기·끄기·되돌리기를 할 때마다 하나씩 올라갑니다. 두 관리자가 동시에 바꿀 때 서로의 변경을 덮어쓰지 않게 합니다.

- 규칙 하나: 화면을 연 뒤 다른 관리자가 먼저 그 규칙을 바꿨으면 409 `rule_override_conflict`로 거부합니다. 화면은 최신 상태로 다시 그리고 그 사실을 알려 줍니다. 최신 상태를 보고 다시 결정하세요.
- 일괄 변경: 미리보기 뒤에 같은 도구에서 다른 변경이 있었으면 아무것도 바꾸지 않고 거부합니다. 화면이 "그 사이 다른 변경이 있었습니다"를 알리고 다시 미리보기를 보여 줍니다. 새 미리보기를 확인한 뒤 다시 확인합니다.
- 대상이 너무 많으면 `bulk_too_large`로 거부합니다.

관리자 규칙 변경은 분석 조건에 들어가므로, 바꾼 뒤의 다음 주기 분석은 같은 커밋이어도 "변경 없음"으로 생략하지 않고 다시 분석합니다.

## 규칙별 기본 심각도

ruff와 ESLint는 결함에 심각도를 주지 않으므로, PJGuardian이 규칙마다 기본 심각도(critical, high, medium, low, not_defined)를 정해 둡니다. 규칙 목록과 상세의 {{ui:rules.col.severity}}에 보입니다.

- 분석에서 새로 감지한 결함에만 그 규칙의 기본 심각도를 넣습니다. 이미 있는 결함은 분석 때마다 다시 계산하지 않습니다.
- 사람이 바꾼 심각도가 언제나 우선합니다. 한 번 손으로 바꾼 결함은 이후 어떤 분석이나 일괄 채움도 바꾸지 않습니다.
- 결함 목록의 심각도 배지에 마우스를 올리면 "규칙 기본값"인지 "수동 변경"인지 보입니다.
- 자동 부여는 서버 설정 `severity.auto_assign`으로 끌 수 있습니다. 끄면 새 결함은 not_defined로 들어갑니다.

### 기존 결함에 기본 심각도 채우기

기본 심각도가 생기기 전에 만들어진 결함(not_defined)은 서버 명령으로 채웁니다. 웹 화면에서는 실행할 수 없습니다.

```
php tools/severity_apply.php                 # 미리보기(바꾸지 않음)
php tools/severity_apply.php --apply         # 실제로 채움
php tools/severity_apply.php --project=<id> --apply
```

- 기본은 미리보기이고, `--apply`를 줄 때만 바꿉니다. 실행 전 백업 명령도 함께 출력합니다.
- 사람이 바꾼 심각도는 어떤 옵션으로도 건드리지 않습니다. 바뀐 결함에는 "규칙 기본 심각도 적용" 이력이 남습니다.
- 중간에 멈춰도 다시 실행하면 남은 것만 처리합니다. 결함이 아주 많으면 워커가 한가할 때 실행하세요.
- 도구 버전이 바뀌어 새 규칙이 생기면 아래 첫 명령으로 매핑과 도구의 규칙 목록을 대조합니다. 매핑 파일을 고친 뒤 이미 자동으로 붙은 값까지 다시 계산하려면 두 번째 명령을 씁니다.

```
php tools/severity_coverage.php
php tools/severity_apply.php --reapply-auto --apply
```

## 문제 해결

- 켠 규칙이 결과에 나오지 않음: ruff 프로젝트에 업로드한 ruff 설정 파일이 있는지 봅니다(규칙 설정 탭 요약의 프로젝트 수). 맞지 않는 ruff 규칙 쌍을 함께 켰는지도 확인합니다.
- 규칙 설명이 최신 도구 버전과 다르다는 안내가 보임: 워커가 시작할 때와 {{limit:rules.load_interval}}마다 규칙 데이터를 다시 읽습니다. 바로 갱신하려면 규칙 화면의 {{ui:rules.reload}}를 누릅니다(워커가 실행 중이어야 처리됩니다).
- 일괄 변경이 계속 다시 미리보기로 돌아감: 다른 관리자가 같은 도구의 규칙을 바꾸고 있습니다. 잠시 뒤 다시 시도하세요.
