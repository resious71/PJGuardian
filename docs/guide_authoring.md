# 가이드 작성·유지 규칙 (P29)

가이드 본문은 코드와 함께 배포하는 **읽기 전용 마크다운**이다(화면에서 편집하지 않는다 — FAQ만 P29B에서 화면 편집). 한국어·영어 두 벌을 같은 구조로 쓴다.
**사용자에게 보이는 기능을 바꾸면 해당 가이드 절(ko·en)을 같은 커밋에서 고친다.**

## 1. 위치(모두 `public/` 밖 — PHP로만 제공)

| 경로 | 내용 |
| --- | --- |
| `resources/guide/user/{ko,en}/<번호>_<key>.md` | 사용자 가이드 절(로그인한 모든 사용자) |
| `resources/guide/admin/{ko,en}/<번호>_<key>.md` | 관리자 가이드 절(admin만 — P29C가 본문을 채움) |
| `resources/guide/{user,admin}/img/` | 그림(`<slug>.png` 공통 또는 `<slug>.ko.png`·`<slug>.en.png`) |
| `resources/guide/screenshots.json` | 그림 목록(재생성 스크립트가 읽음) |

화면: `/guide`(=사용자 가이드), `/guide/user#<key>`, `/guide/admin#<key>`, `/guide/errors#<코드>`, `/guide/licenses`. 탭 정의는 `Services\Guide\GuideTabs` 한 곳(P29B의 FAQ 탭 `/guide/faq`도 여기에 한 줄). FAQ 본문은 이 규칙(파일·자리표시자)을 따르지 않고 관리자가 화면에서 DB에 쓴다 — 같은 안전한 마크다운 부분집합(이미지·자리표시자 없음), 초안용 출처 목록 `docs/faq_sources.md`.
**X16 FAQ 시드**: 기본 질문은 `resources/faq/seed.ko.json`(관리자가 `tools/faq_import.php`로 넣음)에 있고 답변 끝에 사용자 가이드 절 링크(`/guide/user#<key>[/<소제목 slug>]`)를 단다. **사용자 가이드 절 key·소제목을 바꾸거나 화면 문구(큰따옴표로 인용한 단추·메뉴 이름)를 바꾸면 시드도 함께 고친다** — `FaqSeedTest`가 링크·소제목 앵커·인용 문구를 검사해 잡는다. 이미 DB에 들어간 FAQ는 도구가 덮어쓰지 않으므로 운영 중인 내용은 관리자가 화면에서 고친다.

**절 = 한 페이지(X11)**: 사용자·관리자 가이드는 한 번에 한 절(파일 하나)만 본문에 보인다. 주소 규칙:

- `#<key>` — 그 절. 해시가 없으면 첫 절(`order` 최소), 없는 key는 첫 절 + 안내 한 줄(주소도 첫 절로 고침).
- `#<key>/<소제목 slug>` — 그 절의 그 소제목(`##`·`###`)으로 스크롤·포커스. slug는 소제목 글자를 소문자로, 한글·영문·숫자 외는 `-`(같은 절 안 중복은 `-2`). 소제목 글자를 바꾸면 slug도 바뀌므로 외부에서 소제목 앵커로 링크하지 않는다(절 링크 `guide:<key>`만).
- 도움말 링크·오류 코드 "자세히 보기"·북마크는 `#<key>`라 그대로 동작한다. 서버 주소 `/guide/user/<key>`는 만들지 않았다.

## 2. 파일 형식

```
---
key: upload
title: 업로드
order: 3
summary: 한 줄 요약
keywords: 업로드, ZIP, 폴더
related: upload-errors, analysis-status
audience: user
---
## 소제목
본문 …
```

- `key`: 영문 소문자·숫자·`-`(ko·en 파일이 같은 값, 파일 이름 `<번호>_<key>.md`). `order`: 정수(목차 순서). `related`: 다른 key.
- 절 제목은 머리말 `title`이 그리므로 본문은 `##`부터. 한 파일 = 한 절 = 화면 한 페이지.
- **분량**: 한 절은 화면 한두 쪽(1280px에서 스크롤 두세 번) 정도를 권장한다. 길어지면 절을 나눈다(새 key — 링크·도움말 링크 갱신).
- **소제목**: `##`는 절 안의 큰 덩어리(보통 4~8개), `###`는 그 안의 항목을 나눌 때만. 한두 문단마다 소제목을 다는 남발은 피한다. `##`가 3개 이상이면 화면이 절 위에 "이 절의 내용" 미니 목차를 자동으로 만든다.
- **불릿 모양은 화면이 그린다**(본문에 `●`·`▪`·`•` 같은 표식 글자를 쓰지 않는다): `##` = 채운 원, `###` = 작은 네모, 목록 `-` = 점(중첩 단계마다 점 → 빈 원 → 네모), `1.` = 번호. 표식 색은 본문 글자색과 같다(X10 — `--color-text`, 테마를 따라감. 별도 토큰 없음). 제목 글자색도 수준과 무관하게 같고 모양·크기·굵기로 구분한다. 그림·코드 블록은 영향 없음.
- 마크다운은 화면 렌더러(`public/assets/js/lib/markdown.js`, P22) 범위만: `##`·`###`, 문단, `-`·`1.` 목록, `**굵게**`, `*기울임*`, `` `코드` ``, 코드 블록, 링크. **표·인용·원시 HTML·중첩 목록 없음.**
- 링크: `[글](guide:<key>)`(다른 절), `[글](/앱/경로)`(앱 화면), `https://…`. `http:`·`javascript:`·`data:`는 쓰지 않는다.
- 그림: `![대체 텍스트](guide-img:<slug>)`(대체 텍스트 필수, 각 언어로). 그림 안 글자에 기대지 말고 본문에도 같은 내용을 글로 쓴다.

## 3. 자리표시자(서버가 채운다 — 모르는 형식은 시험 실패)

| 형식 | 결과 |
| --- | --- |
| `{{limit:<섹션.키>}}` | 지금 설정 값(환경 변수 > settings.local.ini > config.ini > 기본값)을 단위와 함께 — 크기 `1 GiB`, 기간 `30분`/`30 minutes`, 정수는 숫자만(단위 글자는 본문에) |
| `{{version:app\|ruff\|eslint}}` | 앱 버전, 지금 분석에 쓰는 도구 버전(없으면 "설치 안 됨") |
| `{{ui:<문구 키>}}` | 화면 문구(PHP `src/Lang` 또는 JS i18n, ko·en 모두 있어야) — 단추 이름이 화면과 늘 같게 |
| `{{legend:icons}}` | 아이콘 범례(레지스트리 `icons.json`에서 자동, 관리자 그룹 제외). **사용자 가이드에서 혼자 한 줄로만**(지금은 "화면 읽는 법" 절) — X10. X12부터 카테고리마다 구역 하나(소제목 모양 제목 ● — X13부터 "이 절의 내용"에서는 뺌(`data-toc="skip"`, 본문·`#key/<slug>` 이동은 그대로), 표 caption)를 위에서 아래로 쌓고, 행마다 큰 아이콘(24px) 하나, 네 열은 줄바꿈 없음. X13: 모든 표가 같은 열 폭·같은 전체 폭(화면이 모든 표의 가장 긴 칸 + 여백(아이콘 열 +12px·글자 열 +16px — P29C에서 영어 1280px 넘침 때문에 줄임)을 재서 CSS 변수로 — 위아래 열 경계가 맞음), 표 바탕 = 화면 바탕(`--color-bg`, 머리는 굵게만), 모든 선은 `--guide-legend-border` 1px(좁으면 표 영역만 가로 스크롤). 스타일 가이드 범례는 그대로 |
| `{{icon:<의미 이름>}}` | 아이콘 + 접근 가능한 이름(`public/assets/icons/icons.json`). 바로 뒤에 `{{ui:…}}`가 오면(예: `{{icon:action.upload}} {{ui:upload.start}}`) 이름 글자 없이 꾸밈 아이콘만 그린다 — 단추 이름이 두 번 보이지 않게 |

설정으로 바뀌는 수치(한도·시간·기본값)는 본문에 숫자로 쓰지 않는다. 고정 규칙(상태 이름 등)은 그대로 쓴다.

## 4. 문체

- 한국어: 존댓말(합니다/하세요), 짧은 문장, 동작은 단추·메뉴 이름으로. 용어는 `docs/i18n_glossary.md`.
- 영어: 짧고 자연스럽게, en 화면 문구·용어집과 같은 낱말.
- 절 순서: 무엇을 하는가 → 단계 → 주의·자주 하는 실수 → 관련 절.
- **확인한 사실만** 쓴다(코드·`docs/`·`docs/results/`·화면 문구). 확인하지 못한 동작은 쓰지 않는다. 관리자 전용 정보(서버 경로·내부 사유·비밀)는 사용자 가이드·오류 코드 탭에 쓰지 않는다.

## 5. 오류 코드·도움말 링크

- 오류 카탈로그(`Support\ErrorCatalog`)의 종류별 가이드 절: 업로드 `upload-errors`, 분석 `analysis-failures`, SSO `login-errors`. 오류 코드 탭은 카탈로그에서 자동으로 만든다(코드·제목·원인·조치). 새 오류 코드를 만들면 문구(`failure.<종류>.<코드>.*`, ko·en)와 해당 절의 설명을 함께 고친다.
- 화면 도움말 링크: `Support\GuideLinks::SCREENS`(템플릿 → [audience, key]). 새 화면을 만들면 여기에 한 줄.

## 6. 그림 다시 만들기

```
node tools/make_guide_screenshots.mjs [--only=slug,…] [--dry-run]
```

- `resources/guide/screenshots.json`의 목록대로 **가짜 데이터 설치본**(`tools/guide_demo/setup.php` — 새 DB·가짜 사용자 Alex Kim 등·합성 결함, 실제 개발 DB·사용자·경로·호스트 없음)을 임시 폴더에 만들고 별도 포트(기본 8098)의 PHP 내장 서버에서 1280px·라이트 테마·ko/en 두 벌을 찍은 뒤 서버를 멈추고 임시 폴더를 지운다.
- 파일당 300 KB·가로 1600px 이하(넘으면 실패 — 자르는 영역을 줄인다), PNG·WebP·JPEG만(SVG 금지). 쓰이지 않는 그림이 있으면 시험이 실패한다.
- 사용자 가이드 그림은 꼭 필요한 화면에만(P29 6장 → X10에서 아이콘 범례 그림을 실제 범례(`{{legend:icons}}`)로 바꿔 5장). 화면이 바뀌면 스크립트를 다시 돌리고 그림을 확인한 뒤 커밋한다.
- 관리자 가이드 그림(P29C)은 최대 8장(지금 4장: 설정 관리 화면·사용자 목록·허용 호스트 구역·시스템 모니터링 화면(P30)), `audience: admin`·`login: demo-admin`(그림마다 로그인 계정 — 기본은 목록의 `login`). 그림은 `/guide/img/admin/<slug>`로 admin에게만 나간다. **개발 PC 경로·실제 호스트가 찍히는 화면(백업·분석 도구·점검)은 찍지 않는다** — 가짜 데이터 설치본이라도 설치 폴더 경로가 화면에 나온다.

## 7. 검사

- `php tests/run.php GuideCatalogTest` — 머리말·key·ko/en 같은 key 집합·related·guide: 링크·자리표시자(ko·en 같은 집합)·금지 문법·그림(파일·대체 텍스트·고아·크기·형식), 오류 코드·도움말 링크의 key가 ko·en 절로 풀림.
- `php tests/run.php GuideHttpTest` — 접근 통제(관리자 가이드 403·본문 없음), 검색 분리, 언어, 이미지 응답.
- 배포 묶음: `php tools/verify_bundle.php <묶음 폴더>` — `vendor/`·가이드 본문·그림이 있고 비밀·개발 파일이 없는지(`docs/vendor_build.md` 4절).

## 8. 바닥글 (X10)

가이드 화면 아래에는 한 줄짜리 바닥글만 있다: 앱 버전 · ruff 버전 · ESLint 버전 · 서드파티 라이선스 링크 · "아이콘의 뜻" 링크(→ `/guide/user#shortcuts-and-icons`, 범례가 있는 절에서는 숨김). 버전이 없으면 "설치 안 됨". 아이콘 범례는 바닥에 두지 않는다.

## 9. 관리자 가이드(P29C)

- 절: `resources/guide/admin/{ko,en}/00_overview` ~ `24_linux-ops`(25절 — X14에서 `01_install`의 배포 묶음을 `02_deploy-bundle`로 분리, P30에서 `20_monitoring`의 감사 로그를 `21_audit-log`로 분리, 뒤 절 번호 +1, key는 그대로). 관리자 화면 도움말 링크는 `Support\GuideLinks::SCREENS`의 `['admin', <key>]`(admin에게만 그림 — 그룹 목록처럼 그룹 관리자도 여는 화면이 있어 `View::page`가 역할로 거름), 설정 관리는 카테고리 탭마다 `GuideLinks::CONFIG_TABS`(화면 스크립트가 탭을 바꿀 때 링크를 고침).
- **정확성 시험**(`GuideCatalogTest::testGuideIdentifiersAndForbiddenStrings`): 관리자 가이드 본문의 백틱 식별자 중 점·밑줄 이름(`config.update`, `repo_auth_failed`)은 설정 키(ConfigSchema)·코드 문자열(src/·tools/의 PHP — 감사 작업 이름 등)·마이그레이션 식별자·`docs/error_codes.md`의 코드·php.ini 지시어 중 하나여야 한다(파일 이름·경로·명령은 건너뜀). `E-SSO-*`는 오류 카탈로그에 있어야 한다. 사용자·관리자 가이드 모두 개발 PC·사용자 폴더 경로(`C:\xampp\`·`C:\PJGuardian` 예시만 허용), 이메일 주소 모양, 토큰처럼 보이는 40자 이상 문자열 금지. 동적으로 만들어지는 감사 사유(접두사 + 코드)는 백틱 없이 쓴다.
- 미검증 항목(Linux 운영 서버, 실제 LDAP/AD·IdP, Apache 실환경)은 "운영 환경에서 확인할 것"(en "Verify in your production environment")으로 표시하고 점검 절차만 쓴다.
- 렌더러 주의: 번호 목록(`1.`) 사이에 빈 줄·코드 블록이 끼면 번호가 1부터 다시 시작한다(`ol`에 시작 번호 없음) — 명령은 목록 아래 코드 블록 하나로 모은다.
