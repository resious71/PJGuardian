## 2. 개발 방식

- **명세 → 단계 프롬프트 → 구현 → 보고 → 확인 → 커밋**을 한 단계씩 반복했다. 명세는 `PJGuardian_requirements.md`(수정 금지)이고, 구현은 `prompts/`의 단계별 프롬프트로 진행했다.
- **프로토타입 먼저**(P03~P06): 위험이 큰 부분(도구 실행·파싱, 결함 시그니처, zip 해제, 청크 업로드)을 먼저 시험 코드로 확인하고, 그 결과를 명세 19.10(프로토타입 검증 반영 사항)으로 확정했다. 이후 단계는 19.10을 앞 장보다 우선했다. 프로토타입 코드는 P32에서 지웠다.
- **P 단계**는 명세의 기능 단위, **X 단계**는 사용 중에 나온 보완·화면 정리 요청이다. 단계가 끝날 때마다 명세 19.10과 다음 프롬프트를 갱신했다(명세·프롬프트 갱신 커밋 22개).
- **격리 확인**: 공유 설정·개발 DB·사용자의 워커를 건드리지 않고, 별도 포트·별도 DB·임시 폴더(나중에는 가짜 데이터 설치본)로 직접 확인했다. 직접 실행하지 않은 항목은 "미확인"으로 적었다(`docs/unverified.md`).
- 개발 환경: Windows 11, XAMPP(PHP 8.2.12 → P27A부터 8.3.35), SQLite, Node.js 24(포터블), 헤드리스 Chrome(puppeteer-core).

## 4. 주요 결정

| 시점 | 결정 | 이유 |
| --- | --- | --- |
| P03~P06 → 명세 19.10 | zip은 `extractTo()` 대신 항목별 `getStreamIndex()`로 읽고 **실제로 쓴 바이트**로 한도 검사 | 선언 크기는 위조 가능 |
| 〃 | 결함 시그니처 = 경로 + 규칙 키 + 정규화 코드 내용의 SHA-256 + 같은 파일 순번 | 줄이 밀려도 같은 결함으로 이어짐 |
| 〃 | ESLint는 업로드된 설정을 통째로 무시하고 서버가 만든 flat config 사용 | 업로드 JS 설정은 임의 코드 실행 |
| 〃 | Windows에서 잠금은 전용 `.lock` 파일만, 디렉토리 열거는 `scandir` | Windows `flock`은 강제 잠금, `glob('*')`은 점 파일 누락 |
| 〃 | `/u` 없이 `\v`·`\R`·`\s` 금지 | 한글 안의 0x85 바이트를 줄바꿈으로 봄 |
| P11B | 보이지 않는 프로젝트는 403이 아니라 **404**, 판정은 `ProjectAccess` 한 곳 | 존재 여부 노출 방지 |
| P12 | 업로드 조립은 요청 안이 아니라 워커에서 | 요청 시간 제한·Apache 부담 |
| P20S | Run 비교 기능 제거 | 히스토리 비교 패널(P21)과 겹침 |
| P19C | 유지되는 결함의 마지막 감지 시각을 행마다 갱신하지 않음 | 결함 10만 건 반영 시 쓰기 잠금이 길어짐 |
| P23 | PDF 내보내기 제외, Excel은 자체 작성 | 외부 라이브러리 최소화 |
| P27D | 색은 `tokens.css` 토큰만 | 다크 테마가 토큰을 바꿈, 명암비 자동 검사 |
| P28B~D | 외부 인증 첫 로그인은 승인 대기, SAML 서명 검증은 라이브러리로만 | 승인 전 권한 없음, 서명 직접 구현의 위험 |
| X17A | 초기 관리자 비밀번호 `admin`(변경 강제 없음, 바꿀 때까지 경고) | 사용자 결정 |
| P31 | 쓰기 잠금 대기 초과는 503 `db_busy`, 웹 연결은 자동 체크포인트 끔 | 동시 사용자에서 응답 지연 방지 |

## 5. 기억할 만한 문제와 해결

| 단계 | 문제 | 해결 |
| --- | --- | --- |
| P04 | 정규식 `\v`·`\R`이 한글을 깨뜨림 | 줄 나누기를 `/\r\n\|\n\|\r/`로 통일(19.10) |
| P13 | zip 항목 100만 개 해제 측정: 216초, PHP 최대 172MB | 항목별 해제 유지, 한도·시간 기준 확정 |
| P14 | 워커 첫 작업 전 생존 신호가 없어 "정지"로 보임 | 시작 즉시 신호 기록, 신호 파일 읽기 재시도 |
| P19C | 대용량 반영에서 마지막 감지 갱신이 쓰기를 오래 잡음 | 행별 갱신 제거, 되채움 도구(`backfill_seen.php`) |
| P31 | 과거 Run 100만 건의 마지막 쪽 조회 4.4초 | 뒤쪽 페이지는 정렬을 뒤집어 조회 → 0.6ms |
| X20 | `OidcLoginTest`가 1/64 확률로 실패 | 시험의 틀린 PKCE challenge가 늘 다르도록 결정적으로 수정 |
| P32 | 배포 묶음에 도구 점검 시료(`samples/`)가 빠져 새 설치에서 ruff·ESLint 사용 불가 | 묶음에 포함, `verify_bundle`이 검사 |
| P32 | `secrets.ini` 줄 나누기에 `/u` 없는 `\R` → 한글 주석이 깨져 키 복원 실패 | 4곳 수정, `KoreanLineSplitTest`가 `src/` 전체 검사 |
| P32 | 설정 여러 값을 한 번에 저장하면 일부 미적용, 1초 안 두 번 저장은 워커가 놓침 | 교차 검증 순서 수정, 내용 해시로 변경 감지 |

## 8. 계산 방법

- 커밋·날짜·시간대: `git log --format='%ad' --date=...`
- 추가·삭제 줄: `git log --shortstat` 합계(단계별은 커밋 제목의 단계 번호로 묶음)
- 파일·줄 수: `git grep -I -c '' HEAD -- <영역>`(텍스트 파일만, `public/assets/vendor` 제외)
- 라우트: `src/routes.php`의 등록 호출 수, 설정 키: `config/config.ini.example`의 키 줄 수, 문구 키: `src/Lang/*.php`의 키 줄 수
- 시험 수: `public function test…`(PHP), `test(`·`it(`(JS) 개수
- 작업 시간: 단계 보고(`docs/results/`)의 시작·종료(사용자 확인·대기 시간 포함, 보고에 없는 단계 제외)
